## 一、问题陈述

GouXiangDB v0.1.0 是一个「单机全功能智能表格 + 知识库 + 画布」产品。`PRD-production.md` 解决的是**「数据敢不敢托付」**（容量、备份、部署、安全底线），企业版要解决的是下一个问题：**「一个组织能不能把它当作日常运转的唯一工作台」**。

主理人给出的六条需求，本质是同一次产品跃迁的六个切面：

1. 数据量从「几千行的个人表」走向「百万行级的组织资产」，性能承诺必须分级、可信；
2. 数据库、文档、画布三类内容目前各自有入口、各自有设置，没有统一的信息架构，组织规模一大导航必然失控（Notion 最典型的社区差评就是「六个月后工作区无法导航，需要专职 workspace architect」）；
3. 权限只有粗角色，无法表达「市场部只能改这几列」「这个分组的文档默认组内可见、但这一篇单独开放给协作方」——管理员不敢把全员放进来；
4. 内容越来越多后，靠目录树找不到、靠人脑记不住，需要项目级语义检索，且检索结果必须能被 AI 调用；
5. 第三方 AI（客户自己的智能体、外部工具）要接入，必须「能用且只能在该账号权限内用」，连接后能理解数据表、文档块语言、画布图元语言的完整操作逻辑；
6. 自带 AI 聊天框 / 原生 AI 体验**本期不做**：原"自带 AI 聊天框与 WorkBuddy 整合"方向已放弃（2026-09-12 决策），第三方 AI 一律经 M6 标准 MCP 接入，内置 AI 体验延后单独立项。

**本期不是加六个孤立功能，而是建一套「组织工作台操作系统」：组织（人/部门/角色）→ 资源树（表/文档/画布与分组）→ 权限（并集授权）→ 语义层（向量化与检索）→ 智能体接口（鉴权 MCP）。** 本期的第六层终点是**标准、协议无关、带鉴权的 MCP 服务，供任何第三方 AI 客户端按账号权限接入**（需求第 5/6 条在本期的落点）；原生 AI 体验（内置聊天框 / 服务端模型编排）**本期不做、延后单独立项**。前五层自下而上依赖，顺序不可颠倒。

## 二、目标用户与新增痛点场景

> 生产化 PRD 的三类画像（内部用户、管理员、运维者）继续有效，企业版在其上**加重管理员与组织场景**，并新增第四类画像。

### 角色 1：内部用户（继承，痛点增量）

- P-U6：数据库、文档、画布入口分散，找一份上周的文档要在三个地方翻；同事发的链接有时能开有时提示无权限，不知道该找谁。
- P-U7：调岗后原来能看的表突然 403、新部门的文档又看不到，没有任何「申请权限」的落点。
- P-U8：全局搜索只能命中表名/记录标题，文档里写过的结论、画布上的批注完全搜不到。

### 角色 2：管理员（画像显著加重，企业版核心决策者）

- P-A7：入职/离职/调岗要在多处开关权限；没有部门树，靠记忆维护「谁属于哪摊事」。
- P-A8：无法按「部门 + 角色 + 个别例外」表达真实组织授权；只能拆表、拆空间，数据关联被破坏。
- P-A9：不知道某个人**最终**拥有哪些权限（三条授权路径的并集结果不可见），权限审计全靠人肉盘点。
- P-A10：文档/画布在分组里默认可见，但个别文档要单独共享；改完分组权限后，不知道哪些单篇被单独改过、会不会被覆盖。
- P-A11：要给外部 AI/自动化工具开接口，但无法限制它只碰特定表和字段，担心智能体越权读写。

### 角色 3：运维者（继承，痛点增量）

- P-O7：本地 embedding 进程怎么部署、占多少资源、挂了会不会影响主系统，没有答案。
- P-O8：MCP 接入凭证如何发放与吊销、调用如何审计，没有抓手。

### 角色 4：第三方 AI 应用 / 智能体开发者（本期新增画像）

- 画像：客户方的自动化开发者或外部顾问，通过 MCP 接入 GouXiangDB。
- P-D1：接入后需要一份完整、自描述的操作说明——数据表怎么增删改查、文档块（block）结构如何读写、画布图元（shape/arrow/group）如何创建与修改；不希望只能靠口口相传的文档。
- P-D2：智能体代表某个真实账号操作，需要服务端强约束，而不是「prompt 里嘱咐 AI 别乱看」。

## 三、竞品 / 对标分析

> 行业基线（企业管理/ERP 知识库）：权限矩阵勾选式配置、组织架构树、权限感知 Function Calling（**LLM 不应知道被限制工具的存在**，而非「知道但不能用」）、自研 RAG 三层漏斗（向量 Top-N → BM25 重排 → 业务规则过滤）。生产化 PRD 已对标 NocoDB / Baserow / SeaTable 的私有化与权限分层，本节不重复，只补企业版六支柱的增量对标（2026-09 检索）。

### 3.1 直接竞品

| 竞品 | 组织与导航 | 权限模型（差评重点） | AI / 开放接口 | 对我们的启示 |
|------|-----------|---------------------|--------------|-------------|
| **飞书（Lark）多维表格 + 知识库** | 云文档/知识库/多维表格同属一个导航体系；知识库有分组层级 | 高级权限＝系统角色（所有者/管理员/编辑者/阅读者，不可改）+ 自定义角色；粒度到**数据表/行/列/视图/仪表盘/文档页**；协作者面板权限与高级角色自动双向映射（授「可管理」即入管理员角色）；2025 年容量升级到单库 1000 万热行、计算进入毫秒级 | AI 字段捷径、插件市场、开放 API；企业版才有的高级权限是明确商业护城河 | ①系统角色 + 自定义角色的双层结构直接借鉴；②**协作者面板与角色双向映射**正是我们「统一面板 ↔ 单内容权限状态双向同步」的成熟先例；③其「毫秒级」是热行/索引口径——佐证我们必须做性能分级承诺，不能一刀切；④列权限＝对列数据的可编辑/可阅读，与字段结构管理权分开 |
| **Notion（Teamspaces）** | 顶层 Teamspace + 页面树；成员可自行加页，灵活但失控 | 权限继承在嵌套页场景**不干净**：给访客分享子页不会自动给父级上下文，出现「落在无导航的孤页」；社区 8 个月内两起访客误见敏感页事故；配权限「需要数小时试探各种继承场景」；大库（数千行）筛选排序明显变慢、深层嵌套内容搜索召不回 | Notion AI 按人加购（+8~10 美元/人/月）；仅 SaaS、无私有部署 | ①这是「导航树＝权限资源树」最大的反面教材：**移动/分享节点必须有权限影响预览**；②我们已裁决工作区统一导航、成员不自由定制，正是规避其失控；③单内容例外必须可视化（徽标 + 例外清单），否则继承关系无人能懂；④私有化 + 一体化检索是我们的差异点 |
| **NocoDB（企业版）** | base/表两级，无文档画布一体导航 | 社区版粗粒度 RBAC；字段级权限、SSO、审计在付费企业版 | 有 REST/Webhook 生态，AI 能力弱 | 字段级权限是付费护城河而非开源标配（生产化 PRD 同结论）；我们在私有化产品里把数据库/表/分组/**字段**四级做齐即形成落差 |

### 3.2 间接替代方案

| 方案 | 替代了什么 | 局限 |
|------|-----------|------|
| **Confluence + Jira（Atlassian 体系）** | 企业知识库 + 结构化数据的传统组合 | 文档与结构化数据两套系统、两个权限体系；20 年积累导致权限概念复杂、维护成本高；无画布一体、无私有化轻量交付 |
| **Excalidraw / tldraw + 通用网盘 + 表格 SaaS 的拼装** | 画布协作与文档归档 | 三样东西三套权限、三处检索；AI 无法跨内容形态理解；画布资产散落在文件里 |

### 3.3 MCP 与向量层的行业实践（技术对标，非产品竞品）

- **MCP 授权（2026 规范口径）**：远程 MCP 以 OAuth 2.1（PKCE + 受众绑定 aud 的短时令牌）为基线；scope 按**工具组**设计（read/write/delete 分组），禁止一个 `full` scope 放开全部；HTTP 边界返回 401 而非工具内报错；工具级粒度之外，**记录级对象策略在服务端代码强制执行**（scope 是外层信封，租户/资源归属在内层判定）；每次工具调用全量审计。
- **画布/文档的机器操作语言已有公开范式**：tldraw 官方与社区 MCP server 已证明「AI 操作画布」的工具形态——30 个工具分 7 类（文档生命周期、图元创建、连线绑定、属性变更、分组/层级、页面管理、查询取数），图元具备类型化 schema（rectangle/arrow/note/frame…，含坐标、尺寸、颜色、箭头绑定 fromId/toId）；另有「读取 .tldr 文件 + CRUD 图元 + 全文检索」的文件式实现。**结论：文档块语言、画布图元语言应当作为带 JSON Schema 的类型化工具集暴露，且随产品能力演进而版本化**——这正是需求第 5 条「连接即暴露全部功能操作逻辑」的落地形态。
- **本地 embedding（数据不出网）**：中文企业知识库的事实标准路径是 BGE 系（BGE-M3，567M 参数，1024 维，需 GPU/约 1.2GB 权重）或 Ollama 承载（CPU 可跑的 nomic-embed-text / bge-m3）；云端可切 OpenAI 兼容接口（通义/豆包/Jina 等）。**EmbeddingProvider 抽象 + 批量 + 缓存是通用做法，模型切换需全量重建**——与 D-1 双模式决策完全吻合。

### 3.4 对标总判断与差异化

用户为什么选企业版 GouXiangDB：

1. **私有化前提下的一体化组织工作台**：飞书/Notion 只有 SaaS，Confluence 是拼装；我们在客户自己的服务器上同时给表、文档、画布与统一权限。
2. **权限模型可解释**：角色 + 部门 + 资源树三条路并集，管理员随时能看到「某人最终权限清单」与「某内容例外清单」——直击 Notion 继承混乱的差评。
3. **语义检索与 MCP 是内建能力而非加价模块**：第三方 AI 接入即获得带权限收窄的完整操作语言（数据表/文档块/画布图元），且越权在服务端被彻底拦截。

| 支柱 B 安全（B1–B9） | B1/B2/B3/B5/B6/B8/B9 继续作为全企业版安全底座：B3 令牌版本号被 MC1 凭证吊销复用，B4 分享链接生命周期被 O6 单内容外链分享复用，B6 审计被 O10/MC7 扩展 |
| 支柱 C 备份恢复、支柱 D 监控、支柱 E CI/部署 | 全部继承，构成 M0–M1；企业版新增的本地 embedding 进程与 MCP 端点纳入其备份/监控/部署清单（见第八节） |
| 里程碑 M1–M4 × 架构 P0–P3 | 重编号为企业版 **M0–M1**（内容一一对应，见第六节映射表），旧文档保留原编号不动 |
| Out-of-scope 条款 | 继续有效（多租户、PG 切换、集群、SSO、实时协同、行级权限等）；企业版新增排除项见第十节 |

## 六、里程碑分期 M0–M7（按产品价值，每段独立可验收、可回滚）

> 原则：每个里程碑结束都是**可发布、可回滚**状态，跑 40 条历史回归用例（`docs/baseline/2026-09-12-regression-cases.md`）+ 企业版新增回归。技术依赖顺序不可颠倒：**先有组织（M2），再有资源树（M3），权限才挂得住（M4）；先有内容与权限，向量索引（M5）与 MCP（M6）才有边界；M6 标准 MCP 即本期 AI 接入的收口点，M7 只做企业版五条主线的总验收（不含任何内置 AI 开发）。**
>
> **与架构阶段呼应**：M0–M1 与旧架构 P0–P3 的映射沿用旧 PRD §6.1，不改；M2–M7 的企业架构阶段编号由架构师在企业版架构方案中锁定（建议 EA0–EA5：组织模型 → 资源树迁移 → 权限引擎 → 向量子系统 → MCP 服务 → 企业版总验收，其中 EA5 为纯验收阶段、不含 AI 整合开发），本表先给内容级映射，评审后回填编号。

### M0：生产基座（内容＝旧 PRD M1 + P0 安全网部分）

- 价值：数据敢托付的底线先成立——CI 质量门、SQL 分页、慢日志、健康端点、安全四项、在线备份与首次恢复演练、裸机部署 runbook、Docker 探针。
- 出口：沿用旧 PRD M1/架构 P0 出口门（CI 全绿、干净机裸机部署成功、恢复演练成功、10 万行档压测报告）。
- 回滚：均为外围新增，纯代码回滚；备份为新增物。

### M1：数据底座达标 + 多端发布（内容＝旧 PRD M2–M4）

- 价值：**首个「可私有部署生产版」**，百万行终验通过、密文异地灾备演练完成、Tauri 多端齐备。
- 出口：沿用旧 PRD M2–M4 全部出口验收；**D3 分级性能口径随终验报告对外定格（哪些场景承诺毫秒、哪些不承诺，一锤定音）**。
- 回滚：附件外置/数据链路改造按架构 P1 快照回滚；FTS/旁路为派生数据可 truncate 重建。
- **M1 结束 = 支柱 1 收口，企业版 M2 起的全部功能都建立在可托付的底座上。**

### M2：组织通讯录（人/部门/角色先立起来，不动资源权限）

- 交付：O1 无限级部门树、O2 成员与账号生命周期（含一人多部门）、O3 系统角色 + 自定义角色与角色成员；管理后台挂入 N1 的左下角工作区设置区（设置全局化的第一批落地页）。
- 产品价值：管理员第一次能在系统里描述「公司长什么样」；此时权限仍沿用旧角色粗粒度，**组织数据先空跑一个迭代，避免组织模型与权限引擎同时上线互相引爆**。
- 出口验收（摘）：建 6 层部门、调岗（移部门/兼岗）、停用账号后该账号立即全端失效；角色成员增删对旧角色权限即时生效；组织数据导出/升级不丢。
- 回滚：纯新增表，不触碰业务数据；旧角色到系统角色的映射采用新列附加，不删旧列。

### M3：统一导航与资源树（表/文档/画布同树）

- 交付：N1 工作区外壳（Logo 区/左下设置区/通用功能预留区）、N2 工作区级一级菜单自定义与权限位过滤（此时权限为粗粒度，过滤逻辑先按旧角色跑）、N3 二级列表、N4 三类内容统一分组树、N5 旧入口迁移与旧链接重定向、N6 移动/删除权限影响预览（先以粗粒度权限展示影响面，M4 后自动升级为并集口径）。**授权策略表 `auth_policies` 随资源树在本里程碑一并建表并冻结 schema 契约（字段、主体来源、动作位、继承关联），但本里程碑不写入业务策略、不启用新权限判定——过滤仍走旧角色；M4 只在此契约上填充与启用，避免两里程碑同时改表引爆。**
- 产品价值：信息架构统一，三类内容第一次长在同一棵树上——**这棵树同时是导航树和 M4 的授权资源树；M4 权限引擎所需的策略表契约也在此时就位**。
- 出口验收（摘）：旧版 40 条回归中的全部功能在新架构有入口且操作路径不超过旧版步数 +1；旧链接 301/内部重定向可达；跨组拖拽必弹影响预览；成员看不到（粗粒度下）无权的导航项。
- 回滚：导航配置为新增配置表；外壳可通过开关退回旧版入口（保留一个迭代的开关，M4 验收后删除开关）。

### M4：统一权限引擎（企业版交互风险最高的一英里）

- 交付：O4 统一授权面板、O5 四级粒度矩阵（含字段结构/数据双语义）、O6 文档画布分组继承 + 单内容三类例外、O7 面板↔单内容双向同步、O8 并集有效权限解析与两视角预览、O9 权限中间件全量收口、O10 审计扩展；**旧分享数据迁移为单内容例外、旧角色映射为系统角色/自定义角色**（升级不损坏已存档数据，见第八节）；**全部存量授权在本里程碑回填进 M3 已建表冻结的 `auth_policies`（旧协作者→直接授予、旧角色成员→系统/自定义角色授予、旧分享→单内容外链例外），回填与启用同一里程碑完成——M3 只建空表契约，不回填；** N2/N6 的过滤与影响预览自动切换到并集口径。
- 产品价值：管理员敢放全员进来，敢按真实组织结构授权。
- 出口验收（摘）：权限矩阵勾选后，列表/详情/导出/API 四条路径对无权字段同口径不返回；分组授权下推时例外清单强制可见、覆盖需显式选择；在文档内单独共享后，面板例外计数实时 +1；「以某人视角预览」与实际登录验证结果一致；存量升级后旧分享链接全部仍可访问且权限语义等价。
- **中断继承（私密开关）EARS 验收**：When 有权限者对单篇文档/单个画布关闭「继承上级分组权限」（`inheritAncestors` 置关，见 O6），系统必须先弹出**二次确认**：列出将因此失去访问的**去重成员数**及其角色/部门清单，并明确提示「创建者/owner 恒可访问，不会把自己锁在外面」；确认后该节点转为 restricted（仅创建者＋直接授权可访问），且本次变更写入审计（O10，含前后继承状态 diff）；When 之后重新打开继承，系统同样提示**将恢复访问的范围**（重新获得继承访问的去重成员数与角色/部门清单）并需确认；未确认前节点继承状态不改变。
- 回滚：授权策略为新表 + 灰度开关（可按工作区切回旧粗粒度权限）；迁移脚本幂等并在迁移前自动快照（复用 C1/C5）。

### M5：项目向量库与全项目检索

- 交付：V1 双模式 embedding（默认本地，含本地进程部署物与档位检测）、V2 异步自动向量化（三类内容）、V3 可重建派生存储与重建工具、V4 混合检索（权限先收敛再召回）、V5 索引治理（敏感字段不索引/覆盖度面板）、V6 检索服务对内开放（供 M6 MCP 消费）。
- **M5 不再被任何 AI 选型阻塞**：原 [WB-1] WorkBuddy 调研回填要求已随主理人 2026-09-12 决策取消（方案放弃、走标准 MCP），M5 出口只对向量/检索本身负责。
- 产品价值：内容第一次「可被找到、可被机器理解」；不影响任何既有功能（向量子系统故障时主系统与编辑链路无感，检索降级为全文）。
- 出口验收（摘）：新建/修改内容后在约定秒级延迟内可被语义检索命中；对无权限文档/字段，向量检索零泄漏（构造对抗用例：用无权内容的独特语句搜索）；模型切换后索引自动重建且期间检索可用；本地 embedding 进程被 kill 后编辑主链路不受影响、队列自动积压恢复。
- 回滚：向量表为派生子系统，关闭开关即退回纯 FTS 全文（架构 P2 已建），业务数据零改动。

### M6：鉴权 MCP 服务

- 交付：MC1 端点与账号绑定凭证、MC2 权限内动态工具过滤与服务端二次拦截、MC3 数据表工具集、MC4 文档块语言、MC5 画布图元语言、MC6 操作逻辑可发现性与可执行工具集的分离裁决、MC7 全量审计与吊销。
- 产品价值：客户的第三方 AI「接进来就能干完整的活，且只能干它身份内的活」。
- 出口验收（摘）：用只读账号凭证连接，tools/list 不出现任何写/删工具且直接调用返回 404/403（工具不存在口径，不泄漏存在性）；用字段受限账号，schema 中无不可见字段；AI 按文档块语言创建文档、按画布图元语言画带箭头绑定的流程图，在 Web 端打开结构完整；破坏性工具必须带确认参数；凭证吊销后下一次调用即失效；MCP 调用全量出现在审计中。
- 回滚：MCP 为独立端点/进程，关闭不影响主产品；凭证可整体吊销。

### M7：企业版总验收（纯验收里程碑，不含任何内置 AI 开发）

- 交付：**组织（M2）/ 资源树与导航（M3）/ 权限（M4）/ 向量检索（M5）/ MCP（M6）五条主线端到端对抗验收**；**从 v0.1.0 基线直升 M7 的全量升级实测**（沿用第八节附加式迁移与抽样核对口径）；全项目回归（40 条历史回归 + 企业版新增回归）；输出企业版验收报告（含五条主线对抗用例结果、性能分级实测、升级抽样核对、审计清单）。本期无内置聊天框/AI2/AI3/AI4 交付物。
- 出口验收（摘）：六支柱 P0 需求逐条闭环；重点强化**第三方 AI 经 MCP 的越权对抗用例**（与 M6 出口三对抗用例同源并在此做组织级大库复测）——只读凭证 tools/list 无写/删工具且直调返回工具不存在口径、字段受限凭证 schema 无不可见字段、构造越权参数调用零泄漏（不泄漏资源存在性与内容）；向量检索越权对抗、权限矩阵四条路径（列表/详情/导出/API/MCP）同口径；破坏性 MCP 工具无 confirm 参数不可执行；凭证吊销即时生效。**不再设聊天回答来源、内置聊天框 prompt injection 等用例（本期无内置聊天 UI）。**
- 回滚：本里程碑不引入新运行时功能，无可回滚代码面；若验收发现缺陷，按对应主线里程碑（M2–M6）既有灰度开关/回滚路径处置，主产品与 M6 MCP 相互独立。

## 七、关键交互冲突清单（评审必须逐条拍板，UIUX 照此出方案）

| # | 冲突 | 为什么是冲突 | 本 PRD 的裁决/方案 |
|---|------|-------------|-------------------|
| C-1 | **导航树 = 权限资源树（一棵树干两件事）** | 导航要灵活（管理员想把同一表放到多个菜单位），授权要求资源有唯一归属（否则继承语义不清）；Notion 的事故全部源于节点关系与权限关系含混 | 资源树中每个资源有**唯一父级**（决定继承）；一级导航项是对资源的**引用**（同一资源可被多个导航项引用），引用不改变继承父级；无权资源的引用对该成员隐藏。移动唯一父级＝改变继承边界，必须走 N6 影响预览 |
| C-2 | **跨组移动/拖放的权限突变** | 表或文档从 A 组移到 B 组，继承权限瞬间切换，可能大批人瞬间失权/得权 | 移动确认弹窗展示：新增可访问 N 人/部门、失去访问 M 人，并要求勾选「同时保留原直接授权成员」选项；移动操作入审计（O10） |
| C-3 | **设置全局化 vs 对象级设置** | 现状设置散落各对象内部，一刀切移走会破坏高频操作（如改字段） | 分层：**工作区级**（成员、部门、角色、安全策略、备份、embedding、MCP、审计）统一下沉左下角；**对象级**（字段设置、视图、文档页面信息、画布页面）留在对象内原位置；两处不重名，工作区设置内不放对象设置入口 |
| C-4 | **分组授权与单内容例外的覆盖语义** | 分组改权限时，已单独共享的文档怎么办？下推会静默改变单篇协作状态，不下推又会让管理员以为授权已生效 | 面板展示例外计数；下推时二选一：**保留例外**（默认，单篇额外授权不被收回）/ **覆盖例外**（需二次确认，列出将被改变的单篇清单）；单内容侧始终显示「继承自分组 + 本页例外」两行可读状态 |
| C-5 | **双向同步的实时性与冲突编辑** | 管理员在面板改分组、作者同时在文档内改共享，两边并发 | 权限数据走同一写路径与乐观锁（沿用 A7）；后提交者收到「权限刚被他人修改」提示并展示最新状态，不静默覆盖 |
| C-6 | **并集授权只增不减（D-2）的可理解性** | 三条来源并集，管理员在角色里收回某权限却发现成员仍可访问（因部门或直接授予），会误判为系统故障 | O8 排查视图对任一权限展示**来源清单**（角色 X / 部门 Y / 直接授予 Z），收权操作提供「查看其他来源并一并移除」入口；产品不提供 deny 开关，UI 明示「并集模式：移除全部来源才会收回」 |
| C-7 | **工作区统一导航与成员个性化的矛盾（D-3）** | 成员希望自己排常用项；主理人已裁决不做个人导航 | 个性化只保留**收藏标记与最近访问**（影响排序，不改结构）；需求评审中如再被提起，以 D-3 挡回，不做个人布局 |
| C-8 | **MCP「连接即暴露全部操作逻辑」vs 最小权限** | 需求要求第三方 AI 接入即理解全部功能逻辑；安全基线要求 LLM 不知道无权工具的存在 | 分离两层：**说明层**（能力清单/文档块语言/画布图元语言文档，已接入即可发现，回答「这类系统怎么操作」）与**执行层**（tools/list 按账号权限动态过滤，回答「你能操作什么」）；说明文档不含任何真实资源标识，读文档无法获知客户数据 |
| C-9 | **向量检索的越权通道** | 传统权限收口在列表接口，但语义检索是新入口：无权文档若进入向量库，模型可能通过召回片段泄密 | 召回前先按调用者权限计算可索引资源集合，向量检索带资源范围过滤（SQL where + 向量 ANN 的过滤范式，由企业架构落方案）；不可见字段不建独立向量或在召回后按字段投影剔除；V4 设对抗验收 |
| C-10 | **外链分享（旧 B4）与团队共享（新 O6）概念重叠** | 两套「共享」会让用户困惑 | 单内容权限面板统一为两个动作分区：**团队内共享**（成员/部门/角色，受统一权限面板同步）与**外部分享链接**（走 B4：有效期/密码/吊销/访问记录）；面板中外链以独立类型计入例外 |
| C-11 | **旧版功能与呈现「全部保留」vs IA 重排的肌肉记忆** | 入口搬家必然引发老用户不适 | N5：旧路径服务端重定向 + 一次性引导（可关闭，不再出现）；字段/视图等对象内交互**像素级不动**；验收含老用户任务完成时长对比（不得显著劣化） |
| C-12 | **删除部门/角色的授权悬挂** | 部门或角色删除后，其授权记录与成员归属如何处理 | 删除前强制选择成员去向（调岗/兼岗解除）；角色删除要求先清空成员或指定替代角色；直接授予关系不依赖角色存在，悬挂授权在 O8 视图中显红可清理 |

| 类别 | 要求 | 优先级 |

| 性能：分级承诺（D3） | ①物理字段索引命中：50 万行 P95 < 800ms、100 万行 < 1.5s；②关联 hydration 按架构 P1 口径；③计算字段不承诺毫秒、大表排序筛选禁用并提示（沿用旧裁决）；④语义检索 P95 < 500ms（本地 GPU 档），CPU 档与云端档在管理页展示实测档位，不做统一硬承诺 | P0 |
| 权限判定性能 | 单次请求权限判定为本地缓存快照判定，部门无限级树展开不得产生 N+1；组织/授权变更后秒级生效；成员 500 人、资源 10 万节点规模下，登录后首屏导航渲染 < 1s | P0 |
| 向量化时效与吞吐 | 单条内容新增/更新后，常规积压下 30 秒内可被语义检索命中；批量重建有速率档位，不挤占在线请求资源（与写串行队列协调） | P1 |
| 可用性：子系统故障隔离 | 本地 embedding 进程、MCP 端点为独立进程：任一崩溃不影响主应用；向量队列积压可自动恢复；MCP 网关重启不断已建立的 Web 会话 | P0 |
| **升级不损坏已存档数据** | 所有企业版迁移只做**附加式演进**：新表/新列承载新模型，旧数据按映射脚本迁移（旧角色→系统/自定义角色、旧协作者→直接授予、旧分享→单内容外链例外、旧分组→资源树节点）；迁移前强制自动快照（复用 C1/C5）；迁移幂等可重跑；**从 v0.1.0 基线直升到 M7 的路径必须实测**，每里程碑回归含「升级后抽样核对」：记录数、附件、文档正文、画布图元、分享链接可访问性逐项比对 | P0 |

| 可部署性增量 | 本地 embedding 运行时纳入裸机部署包与离线依赖清单（模型权重支持离线预置目录）；MCP 端点经 Caddy 同域反代，不新开不可控端口；CPU 无 GPU 机器默认装配 CPU 档模型 | P0 |

| 图标方案 | 统一 SVG 图标库（架构师选型锁定），禁止 emoji；导航、通讯录、权限面板图标语义一致（如同一个「分组」图标在三类内容中形态统一） | P0（团队规则） |

## 九、数据埋点方案（企业版增量）

> 沿用旧 PRD 埋点总原则：私有部署数据不出内网、自建 `trackEvent()`、不采内容原文。以下为企业版新增事件，与旧表合并执行。

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 组织 | `department_created`, `member_moved`, `member_deactivated`, `role_created`, `role_member_changed` | 组织变动规模与频率，不含人名内容以外的隐私字段 |
| 导航 | `nav_customized`, `nav_item_opened`, `nav_move_preview_shown`, `nav_move_confirmed` | N2 自定义采用率；C-1/C-2 预览是否真的被看（曝光→确认转化） |
| 权限 | `permission_granted`, `permission_revoked`, `field_permission_set`, `content_exception_added`, `permission_pushdown_chosen`（值：keep/override）, `effective_permission_previewed`, `access_requested` | 授权动作规模；例外数量趋势（异常增长＝继承模型被绕过的信号）；O11 申请漏斗 |
| 向量 | `embedding_mode_switched`（local/cloud）, `vector_index_lag_breached`, `vector_rebuild_started/completed`, `indexing_skipped_sensitive` | 双模式实际选择；积压健康度；敏感字段不索引使用率 |
| 检索 | `unified_search_executed`（类型/结果数/耗时，不含 query 文本）, `search_result_opened`, `search_zero_result` | 混合检索可用性与零结果率；query 内容默认不采集 |
| MCP（含第三方 AI 接入观测） | `mcp_credential_issued/revoked`, `mcp_tool_listed`（工具数）, `mcp_tool_called`（工具名/账号/耗时/状态）, `mcp_permission_denied`, `mcp_rate_limited`, `mcp_destructive_confirmed/blocked` | 第三方 AI 真实使用面；越权尝试是最高优先级安全信号；破坏性工具 confirm 情况可观测 |

> 本期无内置聊天框，原 AI 类事件（`ai_chat_sent` / `ai_source_cited_clicked` / `ai_action_*` / `ai_prompt_injection_blocked`）**本期不埋**，随未来内置 AI 立项再补；prompt injection / 越权诱导在本期通过 MCP 的 `mcp_permission_denied` 与服务端权限中间件观测。

公共属性延续旧规：`instance_id`、`timestamp`、`role`、`version`、`device`；MCP 事件附加 `credential_id` 脱敏标识。

## 十、验收标准（Given/When/Then 摘录）

**支柱 1**

- Given 一张 100 万行、筛选字段已建索引的表，When 普通成员按物理字段筛选并翻页，Then P95 < 1.5s；When 其尝试对超阈值计算字段排序，Then 入口置灰并看到「计算字段大表下不支持排序/筛选」提示，不发生全表计算。
- Given 对外任何性能材料，When 出现性能描述，Then 必须区分「索引物理字段」与「计算字段」两种口径，禁止无差别「毫秒级」表述。

**支柱 2**

- Given 管理员在工作区导航添加一个指向某数据表的一级项，When 一个无权该表的成员刷新，Then 导航中不出现该项，且直接访问 URL 返回受控 404。
- Given 一个文档位于 A 分组，When 管理员将其拖入 B 分组，Then 弹出影响预览（新增/失去访问的人数与部门），确认后才生效，动作入审计。
- Given 旧版用户持有旧 URL，When 升级后访问，Then 自动到达新架构对应页面，不出现 404 白屏。

**支柱 3**

- Given 某成员经角色获得表 A 只读、经部门获得同表编辑、无直接授予，When 其打开表 A，Then 并集结果为可编辑；O8 视图同时列出两条来源。
- Given 管理员对「薪酬」字段设置某角色不可见，When 该角色成员通过列表、详情、CSV 导出、全局搜索、MCP 任一途径读取，Then 该字段不存在于任何响应中。
- Given 文档分组 G 默认组内可阅读，作者对单篇 D 设置了外部协作方团队共享，When 管理员在统一面板把 G 改为「仅编辑者可读」并选择「保留例外」，Then D 对协作方仍可访问，面板显示 1 个例外；选择「覆盖」时系统先列出 D 再要求二次确认。
- Given 作者在文档内刚把 D 共享给某人，When 管理员 5 秒内打开统一面板，Then G 节点显示例外计数 1 且清单含 D。
- Given 从 v0.1.0 升级到 M4 版本，When 迁移完成，Then 旧分享链接逐条可打开、权限语义与升级前等价，记录/附件/文档/画布抽样核对零差异。

**支柱 4**

- Given 默认本地 embedding 模式，When 抓包或断网观察，Then 无任何内容文本发往外网；切换云端模式时出现二次确认与外发说明。
- Given 一条仅存在于某成员无权文档中的独特语句，When 该成员用语义搜索检索该语句，Then 结果中零命中、零片段泄漏。
- Given 管理员切换 embedding 模型，When 切换生效，Then 旧向量被标记作废、全量重建自动开始，重建期间统一搜索退回全文匹配且无报错。
- Given 本地 embedding 进程被终止，When 用户继续编辑记录与文档，Then 保存成功无感知，进程恢复后积压内容自动补索引。

**支柱 5（MCP）**

- Given 一张只读账号的 MCP 凭证，When 客户端连接并请求 tools/list，Then 返回中不含任何写/删工具；直接构造写工具调用返回与「工具不存在」一致的受控错误。
- Given AI 客户端完成连接，When 其请求操作说明资源，Then 可获得数据表、文档块、画布图元的完整语言说明；但说明中不含该实例的任何真实库名/数据。
- Given AI 按画布图元语言创建三个矩形与两条箭头绑定，When 用户在 Web 画布打开，Then 图元、坐标与绑定关系完整正确。
- Given 管理员吊销某凭证，When 持有该凭证的客户端发起下一次调用，Then 立即被拒（不等待令牌自然过期）。

**支柱 6（AI 接入＝M6 标准 MCP，无内置聊天框）**

- Given 第三方 AI 客户端持**只读凭证**经 MCP 接入，When 其请求 tools/list，Then 仅见读类工具与权限内库表 schema，写/删工具不出现且直接调用返回"工具不存在"口径；不泄漏存在性。
- Given 第三方 AI 客户端持**字段受限凭证**经 MCP 接入，When 其拉取 schema 与读取记录，Then 仅见权限内字段，不可见字段在 schema 与返回中一律不存在。
- Given 第三方 AI 客户端（含被注入越权指令/诱导性 prompt 的客户端）尝试越权调用，When 服务端执行期二次鉴权，Then 越权调用被拦截、返回不存在口径且越权内容零泄漏（与 M6 出口三对抗用例同源，M7 组织级大库复测）；任何破坏性工具缺少 `confirm` 参数不执行。

## 十一、边界条件

| 类型 | 必须覆盖 |
|------|----------|
| 空状态 | 无部门/无成员时通讯录引导；无任何自定义导航时的默认导航；无向量索引（新建库/重建中）检索降级为全文并提示；无 MCP 凭证时接入页引导 |
| 错误状态 | embedding 连接失败（本地进程不在/云端 key 错误）模式测试报错可读；权限计算数据不一致时 fail-closed（宁可不放）；MCP 工具参数非法返回结构化错误；索引队列积压超阈值告警 |
| 加载状态 | 大部门树懒加载；权限矩阵大表分批加载与保存中态；向量重建进度；「以某人视角预览」计算态 |
| 边界值 | 部门层级无限（实测 20 层性能）；一人多部门上限策略；角色数量、单资源直接授予条目数；导航引用数量；单文档分块数与超长文档；向量维度与模型包体积 |
| 并发 | 面板与单内容并发改权限（C-5）；多人同时配置导航；重建索引与在线编辑并行；同一凭证并发调用速率限制 |
| 权限拒绝 | 越权访问资源/字段/管理接口/MCP 工具枚举，统一受控 404/403，不泄漏存在性、不出现 500 |
| 离线 | 本地 embedding 权重离线预置；断网下全功能（含检索，使用本地档模型）；MCP 仅内网暴露 |
| 升级/降级 | 从 v0.1.0 直升 M7 实测；每个企业版里程碑可按开关灰度与回退；回退后新模型数据（如部门）以不损坏旧版本运行为前提（旧版本忽略新表） |

## 十二、Out of Scope（企业版明确排除）

1. **记录（行）级与单元格级权限**：本期权限粒度下限为字段（列）；行级隔离沿用视图/表单手段，单独立项。
2. **SSO/SAML/OIDC、SCIM、AD/LDAP 目录同步、MFA**：沿用旧 PRD 排除项；MCP 的 OAuth 2.1 标准化（MC8）是接口侧能力，不等于企业 IdP 接入。
3. **deny（显式拒绝）权限语义与审批工作流引擎**：D-2 并集模式下不做 deny；权限申请（O11）只做轻量通知-授予闭环，不做审批流。
4. **成员个人导航布局/个人主题**：D-3 已定，仅收藏与最近访问。
5. **公有多租户、高可用集群、PG 切换**：沿用旧 PRD；向量子系统同样以单实例可重建为前提，不引入独立向量数据库集群（Milvus 等）。
6. **实时多人协同编辑（OT/CRDT）**：组织/权限/向量均不依赖协同；乐观锁维持。
7. **AI 自主/越权写入**：**本期 GouXiangDB 无内置聊天框**，故不适用"内置聊天框二次确认"；安全精神改为针对 **MCP 客户端与未来 AI**——任何经 MCP 接入的 AI 都以凭证所属账号身份执行、不获得超出该账号的权限（MC2 服务端强制）；MCP 写权限＝账号本人授权（发凭证即知情授权），**破坏性工具（清空/删除等）必须显式带 `confirm` 参数，由 M6（MC5/MC6）承载**；未来若立项内置 AI，其"写入前二次确认"在该项目内重新约定，不在本期范围。
8. **云端 embedding 之外的数据外发训练**：不接入任何会留存/训练内容的非兼容端点；管理后台只允许配置 OpenAI 兼容协议的企业自担端点。
9. **跨实例联邦检索、跨工作区资源树**：单工作区模型。
10. **移动端原生 App、国际化正式版**：沿用旧 PRD。

## 十三、外部依赖与风险

### 外部依赖（需主理人/客户确认）

1. **[已关闭] WorkBuddy 原生接入调研（旧 [WB-1] / 旧 D-4）**：主理人 2026-09-12 已决策放弃 WorkBuddy 原生方案、改走协议无关标准 MCP，**本项不再是外部阻塞项，也不再需要 WorkBuddy 席位（原 100/300 席）等任何资源决策**；"数据是否入云"在本方案下不再需要单独决策（默认本地 embedding 数据不出网，云端仅为 D-1 客户自配兼容端点）。未来若重启内置 AI，再单独立项并重新确认外部条件。
2. 部署硬件档位：客户服务器是否有 GPU（决定本地 embedding 默认模型档位：GPU 档 BGE-M3 类 vs CPU 档轻量模型）；CPU 核数/内存基线写入部署 runbook。
3. 云端 embedding 备选端点（如启用）：兼容协议的 base_url、key、模型与维度，以及客户对内容出网的书面确认。
4. 组织规模参数：部门层级、总人数、资源总量预估，用于权限引擎与导航渲染的容量档位设计。
5. 第三方 MCP 客户端形态：客户使用的智能体平台是否支持账号绑定凭证 / 是否要求标准 OAuth（决定 MC8 是否提前）。
6. 旧生产化 PRD 的全部外部依赖项（部署环境、异地备份、证书等）继续有效。

## 十四、PM 结论（RoleVerdict，v1.2）

- **裁决：GO（收口后无外部 AI 阻塞项）**。五段强制依赖链：**组织（M2）→ 资源树/导航（M3）→ 权限引擎（M4）→ 语义层（M5）→ 标准鉴权 MCP（M6，即本期 AI 接入收口点）**，建在已规划的生产化底座（M0–M1，旧 PRD 不废止）之上，M7 为纯企业版总验收（五主线对抗 + v0.1.0 直升实测 + 验收报告）。主理人 2026-09-12 已拍板放弃 WorkBuddy 原生 AI，**唯一硬不确定性只剩百万行压测（M1，旧 PRD 已定且有 ADR-0008 退路）**；AI 接入不再有任何选型黑盒。
- **本期 AI 战略＝"把能力做进协议，而不是做一个聊天框"**：交付标准、协议无关、带 PAT/OAuth 鉴权的 MCP，任何第三方 AI 客户端按账号权限接入即得三套操作语言；GouXiangDB 自身不内置聊天 UI、不做服务端模型编排。原 AI2/AI3/AI4 全部移出本期（未来评估），需求第 5/6 条在本期由 M6 完整承接。
- **企业版的护城河是权限可解释 + 私有化一体化 + 内建语义层与 MCP**：角色/部门/资源树并集且随时可盘点（直击 Notion 继承混乱差评），表/文档/画布同树同权限（飞书能力在私有化产品中罕见），MCP「语言可学、无权不可调」兼顾需求第 5 条与最小权限。
- **三个最高风险点必须在架构/UIUX 方案正面回应**：① 导航树＝权限资源树的唯一父级/引用模型与移动影响预览（C-1/C-2）；② 分组授权与单内容例外的双向同步与覆盖语义（C-4/C-5）；③ 向量与 MCP 两条新入口的越权收口（C-9、MC2），均以对抗性验收用例封口。
- **性能口径已按主理人要求分级**：只有「物理字段索引命中」承诺毫秒级（50 万 < 800ms / 100 万 < 1.5s），计算字段明确不承诺、沿用禁用并提示，向量检索按硬件档位分别给口径；任何对外材料禁止无差别「百万毫秒」表述。
- **数据安全两条不可让步的底线**：升级对已存档数据只做附加式演进并实测 v0.1.0 直升；向量永远是可重建派生数据，不进业务一致性备份、模型切换自动重建。
- **刻意不做**：行级权限、deny 语义、审批流、个人导航、多租户、SSO、向量库集群、AI 自主写入——全部书面排除，防止企业版膨胀成平台重建。
