## 0. 设计契约与硬约束

### 0.1 寄存器判定
- 本批三块（工作区壳 / 通讯录 / 权限面板）全部是 **Product 寄存器（产品型后台）**：设计服务于"赢得熟悉感"，对标 Linear / Notion / NocoDB / 飞书管理后台。

- **图标零 emoji**。本文用 `icon="<语义名>"` 描述。优先复用 `components/icons.tsx` 已有的自建 SVG：`database table field doc canvas book users user group grid list share link globe external lock shield settings search more plus check close chevronDown/Left/Right trash download upload refresh restore history eye comment edit copy tags layers alertCircle bell logout mail phone star`。

## 1. 概念模型与信息架构总览

### 1.1 从"以库为顶层"升级为"以工作区为壳"
现状顶层是两类平级资产：智能数据库（base）与知识库（kb），由 `LibrarySwitcher` 切换。企业版在其上方引入一个稳定容器——**工作区（Workspace，团队私有部署，通常一个团队一个）**：

```
工作区 Workspace（私有部署 / 团队 / 管理员）
├── 工作区导航（工作区级、管理员编排、全员同一套、按权限过滤）
│     └── 一级导航（管理员编排：nav_node 容器节点 + 可重复的 menu_items 快捷引用）
│           └── 二级内容菜单：数据表 · 文档 · 画布（三类各自可分组）
│                 └── 分组（组织单元；本期同时作为预留授权单元，见 §4.7）
│                       └── 具体内容（物理上仍属于某个 base / kb）
├── 组织与权限（通讯录 / 角色 / 统一权限面板 / 分享与嵌入）
└── 工作区通用设置 + 通用功能扩展区（左下角）

资产物理归属（不变）：
  base ── tables ── fields/records/views
  kb   ── docs(doc|canvas)，doc 有 parentId 树
```

**关键原则：菜单是"引用/编排层"，不是复制，也不改归属。** 一张表/一篇文档物理上仍属于它的 base/kb（权限、回收站、字段、设置仍挂在原资产上），在信息架构中由其**唯一权威父级 `nav_nodes`** 决定归属与权限继承链；管理员把它"放到"某个一级节点、起**导航显示别名**、排到不同位置，产生的都是可重复的**快捷引用 `menu_items`**。这样：① 不搬迁数据；② 现有全部入口与链接保持有效；③ 同一内容可在多处出现，但权限只认唯一父级与内容本身，加快捷方式/排序/别名/删快捷项都不会改权限（避免"拖动=改权限"的误解，两层模型见 §2.4，冲突见 §7-C8）。只有"移动到其他分组/库"才改权威父级。

### 1.2 一级节点的两种形态（解决"可添加具体内容"与"点一级进三类列表"的张力）
- **容器节点（主路径）**：如"客户管理""HR 专区"。点击在右侧展开二级菜单，二级用 `[数据表 n] [文档 n] [画布 n]` 三个分区列出被收纳进来的内容，每类可再建**分组**。
- **一级快捷项（`menu_items`，可重复）**：管理员可把单个高频表/文档/画布"钉到一级"，同一内容可在多个节点重复添加。点击**直达内容**，同时二级菜单自动定位并高亮其**权威父级 nav_node** 所在容器与类型分区（保证面包屑/上下文不丢）。它只产生快捷引用、不改归属与权限（两层模型见 §2.4）。普通成员若对该内容无有效权限，该快捷项按 §7-C7 过滤。

### 1.3 现状资产如何被收纳（迁移默认值，零入口丢失）
升级后首次进入：自动为每个现有 base 生成一个同名容器节点（收纳其全部 table），为每个 kb 生成一个同名容器节点（收纳其 doc/canvas，保留文档 parentId 层级映射为分组/子项）。管理员可再自由重组。原有 `/base/:id/...`、`/kb/:id/...` 深链全部继续可用，进入后在新壳中高亮对应导航节点。

### 2.4 权威资源节点（nav_nodes） vs 快捷引用（menu_items）

菜单里有两类实体，必须区分——这是"同一内容可多次添加"与"权限继承只认唯一父级"能同时成立的关键：

| 实体 | 多重性 | 作用 | 是否影响归属 / 权限 |
|---|---|---|---|
| **权威资源节点 `nav_nodes`** | 每个表/文档/画布有且仅有**唯一父级** nav_node（容器/分组构成唯一父子树） | 决定内容在信息架构中的**真实归属**与**权限继承链**（向哪个分组/库继承授权） | **是，唯一权威** |
| **快捷引用 `menu_items`** | 同一表/文档/画布可被**多次**添加到任意一级节点/分组 | 仅做入口露出、显示别名、排序 | **否，纯引用** |

- 一级"添加具体数据表/文档/画布"产生的是 **menu_items（可重复、可多处放）**；被引用内容的真实父级 nav_node 不变。
- **别名 / 拖拽排序 / 删除快捷项**：只改 menu_items，不触碰 nav_nodes，因此**不改变真实归属与权限继承**（删快捷项绝不等于删内容或改授权）。
- 只有显式的 **"移动到其他分组/库"** 动作才改 nav_node 父级（=改变继承来源），它是与"排序/加快捷方式"分开的独立操作，需二次确认并触发 §4.7 的影响评估，不与普通拖拽混用。

级联关系：
```
工作区 1—* nav_node（容器/分组，构成唯一父子树）
内容资源(table|doc|canvas) *—1 nav_node（唯一权威父级，决定继承链）
nav_node / 分组 1—* menu_item ——引用——> 内容资源（可对同一资源重复多条）
权限过滤：渲染菜单时以"当前用户对该 menu_item 所指资源的有效权限"决定可见；
          无任一可见 menu_item 的容器对普通成员整条隐藏（管理员可见并标灰，见 §7-C7）。
```

## 4. 统一权限面板（核心）

一个面板，覆盖**资源层级 × 主体维度 × 动作**，并与单文档/画布的轻量分享**双向同源**。

### 4.1 资源层级（左侧资源树 / 面包屑）
```
工作区
└─ 智能数据库(base)
   ├─ 数据表(table)
   │   ├─ 分组(group)〔表内分组/菜单分组，授权能力按后端分期，UI 预留〕
   │   │   └─ 字段(field)  ← B7：可见 / 只读 / 隐藏
   │   └─ 字段(field)
└─ 知识库(kb)
   ├─ 分组(group)（文档/画布分组）
   │   ├─ 文档(doc)
   │   └─ 画布(canvas)
   ├─ 文档(doc)（也可在 parentId 树中）
   └─ 画布(canvas)
```
面板顶部资源面包屑可逐级点击（如 `客户管理(base) / 联系人表 / 字段 / 薪酬`），左侧为该层级资源树，树节点带"权限状态角标"（自定义例外数）。

### 4.2 主体三维（segmented：角色 / 部门 / 成员）
三个主体维度切换，共用同一张授权矩阵；一个主体在某资源上的授权来自多条 ACE（访问控制条目）。
- `principalType = role | department | member`。
- 部门主体：授权随部门成员生效，部门成员变动自动跟随。
- 成员主体：即"直接授权"（现有 `DocAclModal` 的按邮箱授权升级为标准直接 ACE，并可溯源）。

### 4.3 动作矩阵（CRUD 语义按资源类型映射）

库 / 表 / 分组 / 文档 / 画布主体动作：
| 动作 | 语义 | 对应既有权限位 |
|---|---|---|
| 管理 manage | 改设置/成员/删除/分享 | `canManageBase` |
| 管理结构 editStructure | 字段/表结构（仅表） | `canManageSchema` |
| 编辑 edit | 编辑记录 / 编辑文档内容 | `canEditData`（文档=编辑内容） |
| 评论 comment | 评论 | `canComment` |
| 查看 view | 只读可见 | `canView` |

字段可见性（收紧机制①，allow 授权上的**能力位裁剪**，不是 deny 某人）：
| 字段可见性 | 含义 |
|---|---|
| 默认 inherit（继承） | 跟随表/分组对该主体的设置 |
| 可编辑 editable | 正常 |
| 只读 readonly | 可见不可写 |
| 隐藏 hidden | 该能力位不含此列：列表/详情/导出/筛选/关联展开一致不出现（§7-C3） |

矩阵勾选组件（沿用 `MembersPanel` 权限表的勾选语言，勾中用 `gx-success` 勾，未给用"—"；字段级用四态 segmented `FieldVisibilitySelect` 而非勾选）。行=主体，列=动作；表头支持"整列授予/清除"。每格即时保存 + 失败回滚 + toast。**矩阵只表达"授予了什么"，没有"拒绝"列。**

### 4.4 权限合成规则（UI 必须能解释清楚，供架构对齐）

**核心边界：三源并集（additive union），不做 deny 某人。** 系统里不存在"对某成员/部门/角色显式拒绝"这一类规则；任何主体的有效权限，只由它命中的**角色(role)、部门(department)、直接授权(direct)** 三类 allow 来源**取并集（按动作取最高者）**得到。要让某人"看不到/只能看"，不通过 deny，而只通过下面**两种收紧机制**实现：

```
有效权限 = UNION_MAX( 三类 allow 来源 )
ACE 来源 source ∈ role | department | direct   （内部成员，三源并集）
另有两条独立轨道：owner-implied（所有者恒最高）、link-share（仅未登录持链人，不影响内部成员）

【收紧机制 ①】字段能力位裁剪（作用在 allow 之上，不是 deny）
   字段可见性 fieldVis ∈ inherit | editable | readonly | hidden
   hidden/readonly 是"授予的能力里不含该字段/不可写"，而不是"对某人设拒绝"。
   这是对三源并集结果的能力位收窄，仅作用于字段。

【收紧机制 ②】内容节点「中断继承」开关（整篇文档/画布私密）
   inheritEnabled = false 时：该文档/画布不再继承上级分组/库的 role/department 授权，
   仅剩 创建者 + 被点名的直接授权(direct)（+所有者恒有权）。
   UI 即 §4.5 的 restricted/锁/"仅指定人员可访问"私密态；重新打开开关即恢复继承。
```

合成规则细则：
- **三源并集、只加不减**：角色、部门、直接授权命中多条时按动作取最高者（与现有 `DocAclModal`"叠加取较高者"一致）；多部门成员取其所有部门授权的并集（见 §7-C14）。
- **不存在 deny 位**：面板里没有"拒绝/禁止某人"这一操作项；要做隔离用"中断继承 + 只点名需要的人"，要藏敏感列用字段 hidden/readonly。
- **所有者**：owner-implied 恒为最高，不能被中断继承或字段裁剪排除。
- **外链**：link-share 只对未登录持链人生效，与内部成员授权是两条轨道，互不升降。

> 与现有 `ShareModal`"分享不降低已有权限"一致：**轻量分享弹窗只做开放向操作（团队可见/可编辑、点名加人、开外链），永不产生收紧**；字段裁剪与"中断继承（私密化）"这两种收紧都只在统一权限面板由有权限者操作。这样两个视图语义不打架（§7-C9）。

### 4.5 继承 / 例外 / 来源追溯的 UI 表达（锁与标记）

资源/主体格上的状态标记（`InheritanceState`）：

| 标记 | 文案（示例） | 图标语义 | token |
|---|---|---|---|
| 继承中 inherited | "继承自 销售运营 分组 · 可编辑" | `inherit`/链路 | 文本 `text-tertiary`，无强调底色 |
| 自定义例外 custom | "已单独设置" | 实心小圆点 | `gx-accent`（每屏少量） |
| 受限/私密 restricted | "仅指定人员可访问（已中断继承）" | `lock` | `text-tertiary`；危险收紧用 `gx-warning` |
| 团队共享 team | "工作区成员可查看" | `users` | `text-tertiary` |
| 外链开启 link | "任何人凭链接可查看" | `globe` | `gx-warning`（提示开放面） |

- **来源追溯 Popover**（`EffectiveAccessPopover`）：点"王珊 在本表 可编辑"旁的来源图标，弹出合成明细：
  ```
  王珊 对「联系人表」的有效权限：可编辑
  ┌ 来源 1（角色）  编辑者(editor) ……… 编辑、评论、查看
  ├ 来源 2（部门）  销售一组@本部门授权 … 查看
  ├ 来源 3（直接）  无
  └ 取最高者 → 可编辑                     [在角色中管理] [在部门中管理]
  ```
  每条来源可点击跳到对应主体的授权位置（溯源闭环）。
- **子资源角标**：资源树节点显示"N 项自定义例外"（字段裁剪、点名 direct、中断继承均计入），点击下钻只看例外项。
- **中断继承开关（收紧机制②的操作位，强制二次确认）**：文档/画布权限头部提供开关"继承上级分组/库的权限"（开=默认 inherited，正常三源并集继承）。这是高危收紧，**关闭开关不立即生效，而是弹出二次确认模态**（复用 §4.7 `BulkImpactConfirmModal` 同一组件范式，不新增弹窗体系）：
  - **触发**：关闭开关 → 弹模态，期间底层状态保持 inherited，取消则原样不动。
  - **关闭确认模态** `BreakInheritanceConfirmModal`（语义图标 `lock`，破坏性提示色用 `gx-warning`/`gx-danger`，间距/圆角全走 `gx-*`）文案骨架：
    ```
    标题：设为仅指定人员可访问？
    副述：关闭后，「Q3 续约方案」将不再继承「客户成功」分组/知识库的权限。

    将失去访问（去重后 18 人）        [gx-warning]
      角色：评论者、阅读者
      部门：市场部、外包协作组
      （同属多个部门的成员只计 1 人；口径见 C15）

    仍可访问
      [users] 创建者：你本人（王珊）
      [star ] 工作区所有者（owner）：始终可访问
      [user ] 已点名协作者（3 人，保持可访问）：
              李伟(可编辑) · 陈晨(仅查看) · Zhao(外部·仅查看)

    [gx-danger 提示条] 此操作会立即收回上述角色/部门的访问；
              创建者与工作区 owner 始终可访问，你不会把自己锁在外面。
    这是切换继承范围，不是对某个人设拒绝（系统无 deny）。

                              [ 取消 ]   [ 确认中断继承 ]（danger 次按钮样式）
    ```
  - **确认后**：节点转 `restricted`，权限头部显示 `lock` + "已中断继承 · 仅指定人员可访问"，并保留"恢复继承"入口；状态经同一 ACL 真源在轻量分享弹窗与统一面板**双向同步**（§4.6 机制不变）。
  - **反向（重新打开继承）也需一次轻确认** `RestoreInheritanceConfirmModal`（`inherit` 图标，非破坏性、以 `gx-accent` 主按钮）：
    ```
    标题：恢复继承上级权限？
    正文：恢复后，上级「客户成功」分组/知识库所授予的角色与部门将重新获得
          对本文档/画布的访问（与当前点名协作者取并集，不会移除点名的人）。
                              [ 取消 ]   [ 恢复继承 ]（primary）
    ```
  - 两个方向都只改变"继承范围"，**不产生任何对主体的 deny**；模态内的失访/恢复人数与角色、部门清单均来自 §4.5 来源溯源的同一组合成结果。
- **字段裁剪标记（收紧机制①）**：某字段对某角色/部门能力位为 readonly/hidden 时，用 `slash`（hidden）/只读标记 + "该角色在此字段为 只读/隐藏（能力裁剪）"；它是"授予的能力不含此列"，措辞不出现"禁止/拒绝某人"。

### 4.6 双向同步：统一面板 ⇄ 单文档/画布分享（本方案的关键）

**一个 ACL 真源，两个视图：**

```
                     ┌────────────────────────────────┐
                     │   权限服务：ACL 唯一真源         │
                     │ (resource × principal × action  │
                     │  + source + version + inherit)  │
                     └───────────┬────────────────────┘
            读/写（同一组 API、同一 version）│
              ┌──────────────────────┴──────────────────────┐
   视图 A：轻量「分享」弹窗                    视图 B：统一权限面板
   （文档/画布内，创建者/可编辑者用）           （管理员，全量继承/字段/部门）
   只暴露高频、开放向操作（不产生收紧）：     暴露全部能力（含两种收紧机制）：
   - 团队可见性（仅可见/可编辑，不降权）        - 角色/部门/成员 × CRUD（三源并集，无 deny）
   - 点名添加协作者（=direct ACE）             - 字段 可编辑/只读/隐藏（收紧机制①）
   - 外链开关/权限/含下级/过期                  - 中断继承开关=整篇私密（收紧机制②）
   - "高级设置" → 深链到视图 B 并定位本资源      - 批量 / 来源溯源
```
> 两视图都不会出现"拒绝某人"：要隔离一篇内容 = 在视图 B 关闭继承并只点名需要的人；要藏敏感列 = 字段 hidden/readonly。

同步机制（全部基于现有 TanStack Query 模式，不引入新范式）：
1. **同 key 同源**：两视图订阅同一查询键（按资源 id）；任一处 mutation 成功后 `invalidate` 该资源及其祖先/后代受影响键。
2. **乐观更新 + version 防并发**：ACE 带版本号；后提交者遇到版本过期 → 提示"权限刚被他人修改，已为你刷新"，不合并不覆盖（§7-C1）。
3. **状态措辞一致**：两视图都用 §4.5 的 `inherited/custom/restricted` 同一套标记与文案，杜绝"两处打架"。
4. **互相深链定位**：
   - 轻量弹窗底部"在高级权限中管理" → 打开统一面板并选中当前文档/画布；
   - 统一面板对某文档"打开内容分享" → 唤起该文档轻量弹窗（编辑器内/列表均可）。
5. **能力越权处理**：可编辑但非管理员的创建者打开轻量弹窗时，涉及"收紧/部门/字段"的操作只在统一面板出现，并提示"需要管理员"；轻量弹窗始终只做开放向、不降权操作。

**轻量分享弹窗（升级 `ShareModal`，合并 `DocAclModal`）线框：**
```
分享 · Q3 续约方案（文档）
当前访问范围： 继承自「客户成功」分组 — 工作区内可查看   [inherit]
  （若已私密则显示：仅指定人员可访问 · 已中断继承  [lock] [在高级权限中恢复继承]）
─────────────────────────────────────────────────
协作者（点名 = 直接授权，可重复添加）      [+ 添加成员/邮箱]
  王珊(编辑)  李伟(查看,外部)  ……                     可改级/移除
─────────────────────────────────────────────────
团队共享（开放向，不降权） ( ) 仅可见  (•) 可编辑
外部链接          [开关]  持链者[仅可见▾] 过期[—]  □同步下级文档
─────────────────────────────────────────────────
字段裁剪(只读/隐藏)、中断继承做"仅指定人可访问"、部门与来源溯源
                                              → [在高级权限中管理]
```
> 轻量弹窗内不提供任何"对某人设拒绝"或隐藏字段入口；私密化（中断继承）只在统一面板执行，弹窗仅如实展示其结果状态。

### 4.7 改上级（分组/库）授权时对已单独设置的子内容：影响预览（防静默覆盖）
当管理员修改一个**有子内容自定义例外**的分组/库权限，保存前弹 `BulkImpactConfirmModal`：

```
你正在修改「销售运营 分组」的权限，将影响其下 36 项内容，
其中 5 项有自定义设置（点名授权 / 字段裁剪 / 中断继承）：
  [查看这 5 项 ▾]
   • Q3 续约方案(文档)  当前：已中断继承，仅指定 8 人可编辑
   • 薪酬调整表(表)     当前：「售前」对 3 个字段为隐藏
   • 客户回访(文档)     当前：额外点名 2 名直接协作者
   • …
如何处理这些自定义设置？
  (•) 保留自定义设置（推荐）—— 其余 31 项应用新授权，这 5 项保持现状
  ( ) 全部恢复为随本组 —— 点名授权保留、但中断继承将恢复继承、字段裁剪将清除
  ( ) 让我逐项选择       —— 进入列表逐项勾选保留/恢复
[取消]                         [应用到 36 项]
```
- "自定义设置"= 三类 allow 侧调整：额外点名 direct、字段 readonly/hidden 裁剪、中断继承；系统内仍无任何 deny。
- 默认项永远是"保留"，绝不静默收紧或放开。
- 选择"恢复"需对危险后果二次提示，尤其：①中断继承的文档恢复继承后，上级角色/部门将重新可访问；②字段 hidden 清除=敏感列重新可见；用 `gx-warning`/`gx-danger`。
- 父级关闭外链或收窄团队默认范围时，同理列出"会被联动影响的子项数量"。

## 7. 状态枚举与冲突交互清单（评审重点）

### 7.1 关键状态枚举（建议作为前端 union / 与后端契约）
```
MemberStatus   = active | invited | disabled
MemberType     = internal | external
DeptFilter     = all | unassigned | invited | disabled
NavNodeKind    = workspace | container | group          # 权威资源节点 nav_nodes，唯一父子树
MenuItemKind   = table | doc | canvas                    # 快捷引用 menu_items，可重复多条
ContentKind    = table | doc | canvas
PrincipalType  = role | department | member
ResourceType   = workspace | base | kb | table | group | field | doc | canvas
Action         = manage | editStructure | edit | comment | view
FieldVis       = inherit | editable | readonly | hidden  # 收紧机制①：allow 能力位裁剪（无 deny）
InheritanceState = inherited | custom | restricted
InheritEnabled = boolean                                 # 收紧机制②：false=中断继承（整篇私密）
AceSource      = role | department | direct              # 内部成员三源并集（取最高）
SideChannel    = ownerImplied | linkShare                # 独立轨道：所有者恒最高 / 外链仅持链人
ShareScope     = private(中断继承) | team | specific | publicLink
```
> 全程无 `deny`/`denied` 枚举：收紧只通过 `FieldVis`（字段裁剪）或 `InheritEnabled=false`（中断继承）表达。

### 7.2 组件 5 态覆盖（Loading/Empty/Error/Populated/Edge）
- 树/列表：骨架行（Loading）、§3.7 空状态（Empty）、网络错误"点击重试"（Error）、正常（Populated）、超长名截断/超深层级缩进/上万成员虚拟滚动（Edge，与 PRD A6 虚拟化一致）。
- 权限矩阵：保存中格内 spinner；无任何 ACE 时显示继承基线说明；超大主体量用懒加载/搜索。

### 7.3 冲突 / 边界交互清单（逐条要有明确处置）
- **C1 两处并发改同一 ACL**：version 乐观锁；过期则提示并刷新，不静默覆盖。
- **C2 上级改动 vs 子项例外**：`BulkImpactConfirmModal`，默认保留例外；重置危险项二次确认（§4.7）。
- **C3 字段隐藏的连带面**：隐藏须在视图、详情展开、筛选器/分组依据、CSV 导出、关联(lookup/rollup)展开、被公式引用处一致处理；保存字段可见性时若该字段被视图/公式/关联引用，给"仍被 N 处引用，相关位置将不显示"提示，避免数据语义错觉。
- **C4 自我/末位保护**：禁止禁用自己、降级自己、移除自己出工作区、改动最后一个 active owner；相关按钮禁用并说明原因。
- **C5 部门删除/移动连带**：成员转未分配或并入指定部门；以部门为来源的 ACE 随部门消亡，成员若还有角色/直接来源则保留相应权限，`EffectiveAccessPopover` 即时反映。
- **C6 外部用户默认隔离**：外部用户默认不进入任何内部库的可见名单，只能经点名 direct 或外链访问；其可访问内容在详情栏清晰列出；外链与外部协作者是两条轨道。
- **C7 导航按权限过滤**：菜单工作区级一套、全员相同，但渲染时按有效权限过滤；普通成员对无任何可见内容的容器不可见；管理员可见空容器并标灰提示"成员不可见"。
- **C8 快捷引用 ≠ 权威父级（防误解）**：添加同一内容到多个一级节点、改别名、排序、删快捷项都只动 `menu_items`，**不改变归属与权限**；真正决定继承的是唯一父级 `nav_node`，只有独立的"移动到其他分组/库"动作才改它（需二次确认 + §4.7 影响评估），不与普通排序拖拽混用。`NavComposer` 中对已成为授权单元的分组显示"此分组已启用授权"角标；未启用授权的纯组织分组点击"权限"时说明"当前权限作用于组内各内容"。
- **C9 分享弹窗开放向 vs 统一面板收紧（无 deny）**：轻量分享弹窗仅开放向（团队可见/可编辑、点名、外链），不降低权限，也不出现"拒绝某人"；隔离整篇内容统一走"中断继承 + 点名"，藏列走字段 readonly/hidden，两类收紧只在统一面板由有权限者操作，两弹窗文案一致、状态同源。
- **C10 禁用账号的会话/链接**：禁用即时失效其登录态与嵌入/分享凭据；启用后恢复；操作结果 toast 说明影响面。
- **C11 树防环**：部门树、文档树禁止拖入自身/子孙（沿用现有校验 + toast）。
- **C12 别名与真名**：导航重命名只改"导航显示名"，菜单中用次级 hint 展示资产真名并提供"恢复与资产同名"；库设置里始终显示真名，避免审计混淆。
- **C13 外链含下级与例外**：父文档开启"同步下级"时，已单独关闭外链的子文档应被识别为例外并纳入影响预览，不被一键打开。
- **C14 多部门成员的角色合成**：成员属多个部门时，部门来源 ACE 取并集最高；来源追溯中分组展示，避免"在 A 部门移除为何仍有权限"的困惑（因 B 部门仍授权）。
- **C15 中断继承影响人数预览的去重口径**：`BreakInheritanceConfirmModal` 中"将失去访问 N 人"必须按**去重成员**计数——同一人经多个角色/多个部门命中只计 1 次（对齐 C14 的多部门并集）；**工作区 owner 与该内容创建者始终豁免，不计入失访名单**（他们恒可访问，防止把自己锁在外面）；当前已点名的直接协作者同样不计入失访、并在"仍可访问"中列出。恢复继承（`RestoreInheritanceConfirmModal`）的人数口径同构，展示"将重新获得访问"的去重人数。人数/名单由后端有效权限合成结果返回，前端只渲染，避免口径前后端不一致。

## 8. 给架构师/前端的契约提示（数据需求，非代码）
- 导航：权威节点 `nav_nodes`（唯一父子树，决定归属/继承）；快捷引用 `menu_items`（可对同一 table/doc/canvas 重复多条、带别名/排序）；按用户有效权限过滤后的可见菜单接口；"移动父级"与"加快捷方式"为两个独立操作。
- 组织：部门树（无限级 parentId/负责人/计数）、成员（多部门、状态、内外部类型、激活凭据）、角色（内置 + 自定义、可授予成员与部门）。
- 权限：**无 deny 的三源并集**——统一 ACE（resource type+id、principal type+id ∈ role/department/member、action、source、version）；内容节点继承开关 `inheritEnabled`（false=中断继承）；字段能力位 `fieldVis ∈ inherit/editable/readonly/hidden`（裁剪而非拒绝）；有效权限合成（三源 UNION_MAX + owner 恒最高）与"成员可访问内容反查"接口；分享链接（范围/角色/过期/含下级）与外部用户独立轨道。
- 同步：ACL 资源与其祖先/后代受影响查询键的失效策略（支撑 §4.6 双向同步）。

## 9. Do / Don't

允许：
- 复用 `gx-*` 全套 token 与现有组件视觉；导航激活态沿用现有左指示条。
- 中高密度、分组清晰、批量操作、来源可追溯、危险操作二次确认。
- 用线性 SVG 图标与克制的单一强调色。

禁止：
- 不新造/硬编码色值，不引入紫→粉渐变、发光、毛玻璃等 AI 模板视觉。
- 不用 emoji 充当任何功能图标或状态（外部/禁用/锁等一律用 SVG + 文案）。
- 不做营销 Hero / "Welcome" 空洞占位；空状态必须给真实引导。
- 不让"改导航"产生"改权限"的错觉；不让上级授权静默覆盖子项例外；不提供无来源解释的"为什么他能访问"。
