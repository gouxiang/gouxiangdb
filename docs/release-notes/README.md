## 编撰规范（所有发布说明统一遵守）

自 0.2.7-beta 起，每一份**对外**发布说明（正式版与测试版一致）都按下面的固定格式写，不再自由发挥：

1. **固定三段结构，顺序不变**：`## 新增` → `## 改进` → `## 升级须知`。
   - **新增**：这个版本新带来、用户能亲手用到的功能；写清楚「在哪里点、怎么用、用完得到什么」。
   - **改进**：对已有功能的修复、优化、体验提升（不是全新功能）。
   - **升级须知**：升级前必须知道的事——是不是测试版、要不要先备份、数据是否迁移、各平台怎么装、首次打开注意事项、哪些开关要管理员开、暂不建议做什么。
2. **客户视角、大白话**：默认读者是非技术使用者。不写内部工单号、提交短码、文件路径、测试数量、安装包哈希等内部信息；这些只进根目录 `RELEASE.md` 的封版台账。
3. **只说本版真实变化**：不堆砌、不夸大；测试版必须在开头与「升级须知」显著标明「测试版」及使用边界。
4. **标题与文件名**：文件名为版本号（如 `0.2.8.md`、`0.2.8-beta.md`）；一级标题为「# <版本号> 更新说明」，测试版追加「（测试版）」。
5. **历史不回改**：每个版本一份说明，随发布定稿；之后不改旧版本说明，只在新版本里说明新变化。需要更长内部记录时另出 `*-internal.md` / `*-full.md`，与对外简版分开。

> 样板：正式版见 [`0.2.3.md`](./0.2.3.md)，测试版见 [`0.2.7-beta.md`](./0.2.7-beta.md)。
