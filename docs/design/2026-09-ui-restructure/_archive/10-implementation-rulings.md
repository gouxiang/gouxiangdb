## 1. D-4 · 更多操作「⋮」入口

### 1.1 最终裁决

> **形态按设计稿：竖向三点 ⋮。显隐按现有实现：默认隐藏，鼠标悬停到该项时才显示。**

这是"设计稿形态 + 实现逻辑"的混合裁决，两者各取一半，冲突点在 §3 C-1。

### 1.2 落地方式（规格）

**图标**（新建 `components/icons.tsx` → `MoreVertical`）：

```
viewBox 16×16，fill 三个圆：cx=8, cy=3.5 / 8 / 12.5, r=1.3
默认色 gx-text-hint #8A94AC → hover 加深 gx-text-2 #5B6785
```

**容器**：20×20，radius 4，内边距 0；hover 背景 `gx-hover`，transition 120ms。

**可见性规则（四条，缺一不可）**：

| 条件 | 表现 |
|---|---|
| 默认 | `opacity-0`，**但占位不撤**（始终占 20×20，避免 hover 时行内文字重排抖动） |
| `group-hover` | `opacity-100` |
| `group-focus-within` / 自身 `:focus-visible` | `opacity-100`（键盘 Tab 到行内可交互元素时显形） |
| 菜单展开中 | `opacity-100`（`data-[state=open]:opacity-100`） |
| 触屏 | `@media (hover: none) { opacity: 1 }`（无 hover 能力的设备常驻显示） |

**无障碍**：`aria-label="更多操作"`、`aria-haspopup="menu"`、`aria-expanded`；`role="menuitem"` 在菜单内。

**菜单内容**（以数据表行为例，顺序固定）：重命名 / 复制表 / 移动到… / 导出 / ——（分隔）/ 删除。删除项 `gx-danger` 色并进 L3 确认（见 `09` §3）。

## 4. D-14 · L2 头部「导入 / 导出 / 分享」

### 4.1 最终裁决（2026-09-18 二次澄清后定稿）

> **L2 头部操作区渲染为一行三列的表格行。前两格（导入 / 导出）＝表级操作；第三格（分享数据）＝数据级操作，即分享表里某一条具体数据。**

- 「表格形态」按我的解读先行落地（一行三列 + 1px 竖分隔），**设计稿已按此更新**，你看图后再定是否调整；备选方案见 §4.5。
- 「分享」你已澄清为**数据级**（单条记录分享），不是表级也不是库级，第三格文案改为「分享数据」。

### 4.2 落地方式（规格）

```
┌ 库级段（D-13）───────────────────────────┐
│ 📦 产品中心              名称 + ⋮         │  ← ⋮ 内含：重命名/设置/成员/回收站（后期）
├ 表级段（D-14）───────────────────────────┤
│ ⬇ 导入   │ ⬆ 导出   │ 🔗 分享数据        │  ← 一行三列，等分，1px 竖分隔
└──────────────────────────────────────────┘
```

| 项 | 规格 |
|---|---|
| 行高 | 28；整行左右内边距 8；与下方数据表列表同宽对齐 |
| 单元格 | 等分 `flex-1`，居中；图标 14 + 文字 12px；radius 4 |
| 状态 | 默认 `gx-text-2`；hover `gx-hover` 底 + 文字提亮；`:focus-visible` 2px 外环；**禁用** `opacity .45` + Tooltip 说明原因 |
| 分隔 | 格间 1px `gx-hairline` 竖线（16px 高，居中） |

**三格各自的作用域与启用条件（关键差异）**：

| 格 | 作用域 | 启用条件 | 禁用 Tooltip |
|---|---|---|---|
| 导入 / 导出 | 当前选中的**数据表** | L2 已选中一张表 | 「请先选择数据表」 |
| 分享数据 | 当前选中的**一条记录** | 表格视图中已选中一行 | 「请先在表格中选中一条数据」 |

**「分享数据」的补充规格**：

- **主入口其实在更贴近数据的地方**：记录抽屉头部右侧操作区（首选）与表格行 ⋮ 菜单（次选）。L2 这格定位是"当前选中行"的快捷入口，三处共用同一个 `ShareRecordDialog`。
- **后端现状**：**无记录级分享接口**（只有库级 `createShareLink(baseId)` 与 KB 文档级 `/api/kb/docs/:id/share`）。因此本期按占位规则（C-7）：入口常驻，点击弹 `PlaceholderHint`「分享数据 · 规划中」；接口就绪后切真实弹窗。
- **预留接口契约（落 `06-handoff.md`）**：`POST /api/records/:recordId/share` → `{ token, url, role: 'viewer'|'commenter', expiresAt }`；公开页路由复用 `/s/:token` 形态（新增 `?record=` 定位），公开页只渲染单条记录（只读视图 + 评论占位，与 Q-8 联动）。

**为什么必须是"一行三列"而不是三个独立按钮**：三格等分 + 竖分隔，视觉上就是表格的一行，与下方"数据表列表"的表格语义对齐，用户在心智上会自然理解为"对这张表的三种操作"，正好解决 `08` §4 里「语义属表还是属库」的歧义。同时库级操作已由 D-13 的上段 ⋮ 承接，两级不再打架。

### 5.2 事实校正（重要）

`08` §5 Q-8 写的是"无任何评论 UI 可消费"，**这条描述不准确**，已核实：

- `RecordDrawer.tsx:143-330` —— 记录抽屉**已有完整评论面板**：`useComments` 拉列表、`addComment` / `removeComment`、计数徽标、展开/收起、删除权限判定（`canManageSchema || canManageBase || 作者本人`）。

结论：**记录级评论不需要预留，也不该动**。真正的缺口是另外三处（KB 文档 / 看板 / 画布）以及数据结构只绑定了 record 一种实体。

## 6. 其余设计项的裁决（规则 6：我的专业建议）

每项给裁决 + 一句话取舍理由。

| 编号 | 裁决 | 取舍理由 |
|---|---|---|
| **D-1** 顶栏库切换器 | 按设计稿**移除** | 两个地方都能切库，会出现"顶栏切了但 L1 选中态没同步"的二义；L1 已是唯一入口，顶栏只留 Logo + 搜索 + 头像 |
| **D-2** ContextBar | 按设计稿**新建** 40px | 视图切换是表格最高频操作，必须有常驻容器承载 Tab + ⋮ + ⚙ + ＋；挂回工具栏会让工具栏过载 |
| **D-3** L2 内容 | 按设计稿＝数据表列表 | 原「全部/未收纳/已收纳」三视角是**菜单编排视角**，不是使用视角；下沉到已存在的 `/workspace/settings/nav` 页面，能力不丢只换入口 |
| **D-6** L2 宽度 | 按设计稿 240 | 256 是与旧壳耦合的历史值；240 与 L1 的 224 形成 16px 节奏差，层级读得出来 |
| **D-7** 抽屉宽度 | **保留可拖拽**，默认 480，范围 [420, 900] | 可拖拽是已实现的真能力，砍掉是净损失；默认对齐设计稿即可。窄端从 340 提到 420，避免拖窄后记录表单折行 |
| **D-8** L1 宽度 | 按设计稿 224 + **新增 56 折叠档** | 顺带修掉 `09` §8 记录的「<1024 断点死交互」：有了折叠档，窄屏才有活路 |
| **D-9** 顶栏高度 | 按设计稿 56 | 48 下搜索框只有 28 高，与 32 的输入控件规格打架；56 是能容下规格的最小值 |
| **D-10** 顶栏通知 | **移除**，位置改「帮助 ?」 | 后端无通知系统，放通知是假入口；但位置空掉会破坏顶栏视觉平衡，改用纯前端即可真实实现的「帮助 ?」（快捷键面板 + 文档链接），真功能占真位置 |
| **D-12** KB 级 ⋯ | 按设计稿**补实现** | `useUpdateKb`/`useDeleteKb` 已定义零调用，成本极低，收益是消除"树上有 ⋯ 却点了没反应" |
| **D-13** KB 级入口 | 放 **L2 头部库级段的 ⋮** | 这是 D-14 歧义的根因：之前没有"库级归属行"，库操作和表操作挤在一处才分不清。拆两段后各归其位 |
| **D-15** 行号 | 按设计稿**补** | 低成本；且行号是键盘导航与"第 N 行报错"的定位锚点，属可用性刚需而非装饰 |
| **Q-1** L2 工具行 | 采纳二分：库级 ⋮ + 表级操作行 | 见 D-13 / D-14，一次解决"属表还是属库" |
| **Q-2** 新页面 | 三条全做占位，首页二期优先 | 与 D-11 一致；首页决定首屏第一印象，优先做实 |
| **Q-3** 通知 | 移除，改「帮助 ?」 | 同 D-10 |
| **Q-4** 抽屉 | 480 默认 + 可拖拽 + 宽度持久化 `gx.drawer.width` | 用户调过一次就该记住，否则每次开抽屉都要重拖 |
| **Q-5** 审计日志 | **不做**，L1 不放入口 | 后端只有 MCP 文件审计，做了也是空壳；二期有数据再加 |
| **Q-6** 导入导出 | 做**最小版** | 导入：列映射 + 行级错误报告；导出：统一走服务端全量（替换"只导已加载页"这个真缺陷） |
| **Q-7** 旧壳 | 新壳稳定后**删 flag 与旧壳**，回退期不出设计稿 | 双壳并行会持续产生"改了新壳忘了旧壳"的漏改；回退靠 git 而非代码开关 |

## 7. 冲突点汇总（明确标注）

| # | 冲突 | 冲突双方 | 处理方式 |
|---|---|---|---|
| **C-1** | 三点显隐 | 设计稿「常驻」 vs 你的指令「hover 才显示」 | **按你的指令**（hover 显示），但补三条合规兜底：`group-focus-within` 显形、触屏常驻、菜单展开时常驻，并且**隐藏时保留 20×20 占位**防止行内抖动。这样既不违反设计意图，也不制造键盘/触屏死路 |
| **C-2** | 底部区项数 | 设计稿 3 项（通讯录/后台设置/回收站） vs 实现 4 项（通讯录/权限管理/导航编排/工作区设置） | **按实现 4 项**，不合并。「后台设置」＝「工作区设置」；权限管理与导航编排是独立已上线路由，收进子项会让直达路径失效 |
| **C-3** | 回收站 | 设计稿放 L1 底部 vs 工作区级无回收站路由 | **已裁决（你）**：UI 定架构、不定死内容；按实际功能放，没有功能就暂时不放，后期可能加。回收站暂不进 L1 底部，底部固定区保留为可增删的行容器，功能上线直接插入 |
| **C-4** | 分享作用域 | 你澄清为**数据级**（单条记录）vs 后端只有库级 `createShareLink(baseId)` | 三处入口（L2 第三格 / 记录抽屉头部 / 行 ⋮）统一文案「分享数据」，作用域＝当前选中记录；接口未就绪期间点击走 `PlaceholderHint` 占位，契约见 §4.2 |
| **C-5** | 「表格形态」语义 | 两种解读：一行三列操作行 vs ⋮ 弹出的表格化菜单面板 | **已按"一行三列"落进设计稿**（你看图后定）；若要换备选方案（§4.5），共用同一组件，一行渲染差异即可切换 |
| **C-6** | 顶栏通知 | 设计稿画了 vs 后端无 | 移除，改「帮助 ?」（纯前端可实现，不是假入口） |
| **C-7** | 占位入口 | 你的指令「预留占位」 vs `09` §1「不放假入口」 | 占位**必须可见地告诉用户它是占位**：行尾「规划中」badge + 点击弹明确反馈。禁止"能点但没反应"。此边界已写入 §3.4 |
| **C-8** | 评论现状 | 你的指令说"功能缺失" vs 实测记录级已完整实现 | 记录级**不动**；预留只做 KB / 看板 / 画布三处。见 §5.2 |
| **C-9** | D-4 hover-only | 你的指令 vs `09` §5.4「禁用 hover-only」 | `09` §5.4 已追加例外条款（条件性 hover-only），两处不再打架 |
