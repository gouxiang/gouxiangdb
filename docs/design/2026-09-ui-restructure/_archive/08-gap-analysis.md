## 1. 三类差异，必须先分清

盘点出来的"对不上"有**三种完全不同的性质**，混在一起会导致错误的工作量估算：

| 类 | 定义 | 数量 | 归属 | 处置 |
|---|---|---|---|---|
| **Ⅰ 类 · 设计缺口** | 交互已实现，但现行设计文档没画 | 405 | 设计缺口 | 本轮补全（见 `09`） |
| **Ⅱ 类 · 设计已定·代码待改** | `03-navigation.md` v3.0 等已明确要求，代码还是旧实现 | 11 | **落地任务** | 不补设计，进重构清单 |
| **Ⅲ 类 · 实现缺陷** | 设计没要求，但代码本身有 bug 或明显不一致 | 约 30 | 技术债 | 建议顺手修，不进设计稿 |

**最容易误判的是 Ⅱ 类**——它看起来像"设计没覆盖"，其实设计早就定了，只是代码没跟上。下面 §4 单独裁决。

## 3. 遗漏点（Ⅰ 类 · 设计缺口）

按严重度分级。**P0**＝不补就会出现"用户不知道发生了什么"或"数据丢失无挽回"；**P1**＝体验明显不一致；**P2**＝打磨项。

### P0 · 异常态与不可逆操作（共 9 组）

| # | 遗漏点 | 现状证据 | 后果 |
|---|---|---|---|
| **P0-1** | **401 会话过期**：硬整页跳转，无提示、无 returnUrl | A-12 / D-01 | 用户看到"页面突然回到登录页"，不知道发生了什么 |
| **P0-2** | **全局 403 无统一处理** | D-05 / E-06 | 三种风格混用（toast 英文原文 / 静默隐藏 / 整块替换），同一权限问题三种面孔 |
| **P0-3** | **危险操作确认强度无分级** | X-01~X-18 | 同一个"永久删除"：删 Base 要输入全名，回收站彻底删除只点一下，批量删除记录**干脆没有确认** |
| **P0-4** | **无撤销通道** | T-05 | 删除记录、清空表、批量删除、撤销授权后，只有一行 toast，无挽回路径 |
| **P0-5** | **表单错误落位无规范** | C-00 / §8.3 | 基座 `Input`/`Textarea`/`Select` **根本没有 error 属性**，业务方四种落位：字段下方 / footer 上方 / 表单底部 / 全走 toast |
| **P0-6** | **弹窗无焦点管理** | M-02 / M-03 | 不自动聚焦、无 focus trap、关闭不归还焦点、**全仓零滚动锁定**、无 `role="dialog"`/`aria-modal` |
| **P0-7** | **保存冲突无界面** | G-14 / D-10 / CT-03 | 表格后写覆盖；文档 409 只 toast「请刷新合并」，无 diff、无二选一 |
| **P0-8** | **断网 / 超时 / 5xx 无全局态** | A-07 / D-07 / D-13 | 断网时登录页显示浏览器原生 `Failed to fetch`；无 AbortController、无 online/offline 监听 |
| **P0-9** | **空态 / 加载态 / 错误态无组件规范** | I-04 / I-05 | **全仓无骨架屏**；EmptyState 有两套组件 + authz 第三类内联卡；错误态各页面自行其是 |

### P1 · 一致性缺口（共 10 组）

| # | 遗漏点 | 现状证据 | 说明 |
|---|---|---|---|
| **P1-1** | **三套弹窗体系并存** | M-00 / X-02 / U-03 | 设计系统 Modal + 8 处原生 `window.confirm` + 2 处原生 `window.alert` |
| **P1-2** | **Toast 只有 3 变体且不可关闭** | T-02 / T-04 | 无 warning（"成功但有问题"无处安放）；无关闭按钮；无 `aria-live` |
| **P1-3** | **权限门控无决策表** | E-02 / E-03 / E-08 / E-09 / E-20 | 同一页面里"禁用"与"隐藏"混用；有的整块替换；有的入口仍在但点进去才说没权限 |
| **P1-4** | **键盘模型未定义** | G-18 / G-20 / D-11 | Grid 无 Tab、无复制粘贴、无 Shift 连选；**虚拟化列表只有窗口内行在 DOM，Tab 到不了未渲染行**；无 `role="grid"`/`aria-*` |
| **P1-5** | **hover-only 操作触屏与键盘不可达** | E-07 / F-15 / SH-16 / A-08 | 二级导航行操作、编排器行操作、文档树 ⋯、部门 ⋯ 全是 `opacity-0 group-hover:opacity-100` |
| **P1-6** | **级联清空不提示** | F-27 / F-43 / NumberRuleEditor | 换关联表清空子字段、换筛选字段清空值、换数据源表清空 filter、改重置方式清字段——四处静默清空 |
| **P1-7** | **数值钳制全部静默** | F-10 / F-49 / U-01 | 精度 0–8、序号位数 1–10、上传大小 1–200MB，越界直接改写数值，无"已修正到边界"提示 |
| **P1-8** | **列表截断无提示** | W-02 / A-43 / D-02 | EntityPickerModal 硬截 200 条无任何提示；SubjectPicker 成员候选只有首屏 100 条且无远程搜索 |
| **P1-9** | **分页到底 / 游标失效态未定义** | G-58 / G-61 / A-19 | keyset 关闭时退化为单页 200 且"加载更多"永不出现；游标 400 **静默回第一页**；成员列表无"已到底" |
| **P1-10** | **同一功能两套实现** | B-10 vs A-14 / G-02 vs G-04 / SH-18 vs SH-56 | 数据库成员面板全量平铺 vs 通讯录有搜索筛选分页；客户端导出已加载页 vs 服务端导出全量；树内联重命名 vs 首页 Modal 重命名 |

## 4. 差异裁决（Ⅱ 类 · 设计已定、代码待改，以及需要你拍板的冲突）

这一节的每一条**都不是设计缺口**，而是需要你确认"按设计走还是按现状走"。

| # | 冲突点 | 现行设计（`03` v3.0） | 当前实现 | 建议裁决 |
|---|---|---|---|---|
| **D-1** | 顶栏库切换器 | **顶栏不再出现库名/切换箭头** | `WorkspaceTopBar` 仍保留 `LibrarySwitcher`，且在 `/workspace/*` 下退化成「选择库」 | **按设计走**（移除）；库切换只在 L1 工作区内完成 |
