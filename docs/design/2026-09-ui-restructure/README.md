## 1. 交付形态（已变更）

2026-09-19 起，**放弃「逐页出页面设计稿」的交付方式**，改为「一套开发可直接执行的设计规范 + 架构图」。原因：逐页稿难以保证页面间逻辑一致，且无法覆盖可预见的新场景。

| 已废弃 | 现行 |
|---|---|
| 逐页 UI 页面稿（S1–S20） | **规则化规范**（以「规则」为单位，标注适用场景 + 正例 + 反例） |
| 多份并行文档（01–10） | **单文件 `UI-SPEC.md`** + 归档目录 |

## 3. 参考设计（唯一源）

**判定顺序**：`UI-SPEC.md` → 参考设计推导 → 现有 token。规范未覆盖的场景一律回落到参考设计推导，**不得自行新增样式**。

## 4. 最高优先级约束

1. 最终重写页面的视觉必须与参考设计**完全一致**，禁止自由发挥或新增视觉风格。
2. 禁止在业务代码里写死 hex，一律走 `gx-*` Tailwind 类。
3. **开工前置**：`packages/design-tokens` 现存 v1 色板（`#378ADD` / 暖灰 `#F1EFE8`）与参考设计（`#3A6DF0` / 冷灰）冲突，**必须先按附录 A 完成令牌迁移**，否则写出来的页面不会与参考设计一致。

## 5. 开发接手方式

1. 读 `UI-SPEC.md` 第 0 章（参考设计源 + 三条硬约束）。
2. 按第 5 章「开发总览清单」从阶段 0 顺序打勾。
3. 视觉争议一律查附录 A/B；验收一律按附录 C 逐项实测。
4. 规范有缺口时：**从参考设计推导 → 回填进 `UI-SPEC.md`**，不在代码里临时发明。
