## ② 发现的问题

### P0-1（已修复）文档末尾空标题块保存后变成字面 `##` 段落
- 现象：斜杠菜单选「标题 1/2」得到空标题块 → 保存 → 刷新后编辑器与公开分享页正文出现字面 `##` 文本（截图 22/23/32）。任何「插入标题后未输入文字就保存」的文档必现。
- 根因（最小复现证实，`npx tsx` 直接对拍）：`packages/blocks/src/blocks.ts:992` `blocksToMd` 出口 `join("\n")...trim()` 把行尾空标题 `"## "` 削成 `"##"`；解析侧 `blocks.ts:529 HEADING_RE=/^(#{1,6})\s+(.*)$/` 要求 `#` 后必须有空白，`"##"` 落入普通段落分支。渲染侧 `packages/blocks/src/markdown.ts:331` 的独立标题正则同样失配。
- 修复（最小改动）：两处正则改为 `/^(#{1,6})(?:\s+(.*))?$/`（CommonMark 语义：`#` 行即标题），取值 `h[2] ?? ""`。
- 自验：web 全量 vitest 102 文件 1241 用例通过；`apps/web` 与 `packages/blocks` `tsc --noEmit` 通过；浏览器实测旧损坏文档重开恢复为 H2（截图 24），公开分享页正常渲染 `<h2>`（截图 32）。

### P1-1（转交·权限语义）文档分享弹窗「内部成员 仅可见/可编辑」必现 404
- 现象：点内部档位 → 红 toast「API 401/404: 接口不存在」（本次为 404），档位回滚（截图 30）。
- 根因：前端 `apps/web/src/api/client.ts:913 setInternalShare` 调 `POST /api/kb/docs/:docId/share/internal`；后端 `apps/api/src/routes/kb/sharing.ts` 只有 GET/POST `/docs/:docId/share`（:15/:51），无 `/share/internal`——逐库逐人成员名册已下线，GET 只回 `internal.membersCanEdit=access.canManage`（sharing.ts:44）。调用链：`ShareModal.tsx:79 applyInternalRole` → `kb-hooks.ts:149 useSetInternalShare`。
- 建议改法：内部访问既然以知识库团队角色为准，弹窗应去掉可写交互、改为只读展示（或由后端补真实端点）。涉及授权语义，未改。

### P2-3（已修复）登录失败 toast 中英混排「API 401: Invalid credentials.」
- 现象：错误密码登录 → toast 显示英文原文+状态码前缀（截图 03）。
- 根因：后端 `apps/api/src/auth.ts:100/116` 返回英文 "Invalid credentials"；前端 `client.ts:194` 包装为 `API ${status}: …`，`LoginPage.tsx` catch 原样 toast。
- 修复：`LoginPage.tsx` catch 中将已知 "Invalid credentials" 翻译为「邮箱或密码不正确」，其余错误保持原文。浏览器实测生效（截图 03-login-wrongpw-fixed）；auth 相关 61 用例通过。
- 备注：`API {status}: {error}` 信封在其它页面仍可能出现中英混排，建议后续统一做错误文案映射表（登记为遗留）。
