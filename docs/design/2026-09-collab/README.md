# 三类内容实时协同编辑 · 大白话说明

> 面向产品负责人。技术细节、接口协议、侵入点清单见同目录 [`DESIGN.md`](./DESIGN.md)。

---

## 这次要做什么

让**文档、画布、数据表**支持多人同时编辑：改动实时互相可见、自动合并，**谁都不会覆盖谁**。

## 界面和操作：保持不变（重要）

引入的只是**同步引擎**（一个不负责渲染界面的底层库），**不引入任何编辑器**。你熟悉的界面和操作**一个都不会变**：

- **文档**：还是现在这个自研编辑器 —— 块类型、快捷键、右键菜单、上下插入热区、大纲、"编辑/源码/预览"切换、版本历史入口，全部原样
- **画布**：还是现在的画布 —— 工具栏、样式条、色板、缩放与框选手势，全部原样
- **数据表**：还是现在的表格与各视图 —— 字段渲染、单元格编辑、筛选/分组/排序、工具栏，全部原样

协同能力是**叠加**上去的，不动原有组件内部：

- 别人的光标是**浮在上面的一层**，不会塞进编辑器内部
- 在线头像是**新增区域**（这就是需求本身）
- 「某格被他人编辑」复用现有的禁用/提示样式，不新造视觉

**验收方式**：单机编辑（没有第二个人在线）时，页面结构与引入前**逐元素一致**。这一条会作为每个阶段的硬性验收项，我会亲自比对。

## 你会看到什么新东西

1. 内容页固定位置显示**一排头像** = 此刻正在看 / 改这个内容的人，进出实时更新
2. 别人打字的地方有**他的光标 + 名字**
3. 某一段 / 某一格正被别人改时，**你改不了那一处**（会提示是谁），但能改别处
4. 通过分享链接进来的外部人显示为**「匿名」**，也能一起协作（前提是分享设置允许编辑）

## 三类内容的情况不一样

| | 情况 |
|---|---|
| **数据表** | **最顺**。它本来就是"一格一格"独立存的，天生适合协同。要补的是「并发保护」—— 现在是后写的直接覆盖先写的。 |
| **文档** | **要动一点结构，但比预想少**。原本担心"每段的编号是临时生成、不存库的"，实测发现**在编辑器里它是稳定的**（不稳定的那种情况只存在于另一个对外接口里，不影响编辑），所以这块不用改。真正要补的是**「光标在第几个字」这个位置模型**（现在完全没有，只有浏览器自带的光标；而段落里存的是带格式标记的原文，屏幕上显示的是格式化后的样子，两者位置对不上，需要一层换算 —— 已完成）。 |
| **画布** | **有明确接入点，比最初预估乐观**。已实测：不需要重建画布就能让对方的改动实时出现，**且不会丢掉你当前选中的图形**（这是我最担心的一点）。两个必须处理的坑：① 图形编号是 5 位随机码，**约 1% 概率重复**，撞号后画布不报错、**直接少一个图形**（已解决：编号前加上"谁创建的"）；② 别人插入我这边**不认识的图形类型**时，界面会持续报错，而且**会让画布内部状态卡住**（已有办法：换成占位图形，不能简单丢掉 —— 丢掉会让后续操作全部错位）。 |

## 分几步做（每步都能独立验收）

| 步 | 内容 |
|---|---|
| **0 · 打地基修补** | 先修两个既有隐患：版本回滚后协同会读错版本；本地环境迁移数不一致 |
| **1 · 实时通道** | 连接、身份、房间、存储、服务端配置（含生产环境反代配置 —— 不配会导致**每分钟掉线一次**） |
| **2 · 文档协同** | 含协同光标、在线头像、"谁在改哪段" |
| **3 · 数据表协同** | 含"哪一格被占用"；勾选 / 拖卡片 / 关联这类操作不会被挡 |
| **4 · 画布协同** | 图形级；图形内的**文字按字符合并** |
| **5 · 权限融合与匿名** | 外部访客、只读访客、降权后自动踢为只读 |
| **6 · 收口** | 全量测试 + 部署验证 + 长时间连线压测 + 备份体积复核 |

## 已知取舍（我判断可接受，你可以推翻）

1. **公式 / 默认值不实时反哺**：服务端算出的值，对方要**刷新或重新进入**才看到（协同内容本身是实时的）。消除它需要额外定义"同一格有两种来源时谁说了算"，建议二期。
2. **落库有 30 秒一档的延迟**：影响的是列表页「最近更新时间」和搜索结果，**编辑本身是即时的**。
3. **画布同一个图形内部同时改**：**文字**能按字符合并；**位置、颜色等其他属性**可能一方被覆盖。这是选定的第一期边界。
