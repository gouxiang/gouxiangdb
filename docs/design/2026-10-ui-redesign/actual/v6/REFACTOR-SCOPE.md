# v6 底板 → 全站 UI 重构 · 施工范围与顺序

> 目标：**只做视觉优化，尽可能不触碰功能**。菜单与数据表需达到与底板**一比一**；其余页面依据底板样式统一优化。
> 本文是「动工时的施工地图」。动工前请先跑 `node scripts/snapshot.mjs` 取当前真实状态（见文末）。
>
> **⚠️ 动工前必须先向戴总确认未决项**（见 `HANDOFF.md` → 「开工前必读：已知冲突、未决项」§1，编号 U1–U4）。
> 未确认前不要动工——尤其 U1 决定一级导航的拟物是保留还是撤回。

---

## 0. 施工铁律（违反即回退）

| # | 规则 |
|---|---|
| 1 | **只改视觉**：`className` / `style` / 令牌取值 / 图标资源。不改 props 语义、不改状态机、不改数据流 |
| 2 | **不改任何 API 契约、数据结构、路由表、权限判定逻辑** |
| 3 | 一次只改一个层级（令牌层 → 壳层 → 页面层），每层独立 commit |
| 4 | 每步跑完四门检查（见 §3），收集数不减、lint/tsc 零错误 |
| 5 | 视觉拿不准时**照抄底板数值**，不自行发明间距/色值 |

## 2. 施工顺序（严格按序，不可跳步）

| 阶段 | 内容 | 说明 |
|---|---|---|
| **阶段 0** | **令牌迁移**（前置，必须最先完成） | 改 `packages/design-tokens/src/colors.ts`：主色 `#378ADD → #3A6DF0`，中性色迁冷灰。**包名与 Tailwind 类名保持不变，只换底层取值**并补齐缺失令牌。规范第 28 行：「不完成这一步，后续所有页面写出来都不会与参考设计一致」 |
| 阶段 1 | 壳层（L1 轨道 → L2 面板 → 顶栏） | 顶带三要素：同高 56px、同线色、中心共线 28px |
| 阶段 2 | 数据表页（P0 核心） | 三行工具条 + 表格，达到一比一 |
| 阶段 3 | 其余页面（P1） | 照底板样式统一 |
| 阶段 4 | 公共组件与浮层（P2） | 状态矩阵覆盖 |

> **为什么阶段 0 必须先做**：底板与规范当前是两套色（见 HANDOFF.md 预警）。
> 若不先统一令牌就重做页面，等于用旧色写新 UI，最终还要再返工一遍。

## 3. 验收标准（可量化，避免"一比一"主观扯皮）

### 四门检查（每步都要过）

1. `vitest` **收集数恒等**（不减）
2. 三包 `tsc` **零错误**
3. `eslint` **零 error**
4. S0 golden **通过**

> 重活走 VM15（`192.168.31.15`）；本机 16GB 只跑 tsc/lint/定向单测/轻脚本，禁全量测试与构建。

### P0 一比一判定（逐条打勾）

- [ ] L1 轨道宽 **76px**；图标砖 36px、圆角 11px
- [ ] L1 图标三态：未选中薄凸起 / 悬停上浮 1px / 选中按下凹槽
- [ ] L1 底部区顺序：新建库(+) → 通讯录 → 帮助中心 → 工作区设置；竖排纯图标
- [ ] L2 面板宽 **236px**；折叠后 **0**
- [ ] L2 面板头高 **56px**，底边线与顶栏 **同色**
- [ ] 二级头底边 y == 顶栏底边 y（**差 < 0.5px**）
- [ ] logo / 二级头 / 顶栏 三者内容垂直中心 **共线于 28px**
- [ ] L2 行项 **无**记录条数徽标
- [ ] 选中高亮覆盖**整行**（含行尾「⋯」）
- [ ] 数据表工具条为 **3 行**，高度约 41 / 45 / 43
- [ ] 1024 / 1180 / 1280 / 1440 四档 **零横向溢出**

## 4. 红线（明确禁止）

| ❌ 禁止 | 原因 |
|---|---|
| 顺手改功能 / 改 props / 改状态机 | 与「只做视觉」目标冲突，且无法与视觉改动一起评审 |
| 自行新增色值 / 间距值 | 规范第 18 行：「规范未覆盖的场景，一律从参考设计推导，**严禁自行新增样式**」 |
| 删除数据源里的 `kind: 'group'` 行 | 排序分段依赖它（详见 HANDOFF.md 契约一） |
| 删除 `.rail-grp` 样式 | 保留以备将来恢复分组 |
| 在本机跑全量测试 / 构建 | 内存纪律，走 VM15 |
| 把 v6 原型 HTML 当组件模板复制 | 自包含 HTML，DOM/样式无法进入 React 组件体系 |
