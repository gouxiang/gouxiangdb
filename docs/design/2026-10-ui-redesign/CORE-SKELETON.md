# 构想工作台 · 核心骨架框架（UI v2）

> 版本 v0.1 ｜ 2026-10-20 ｜ 状态：**框架基础，主题功能的挂载底座**
> 来源：全部基于 `apps/web/src` 真实代码盘点（路由来自 `App.tsx`，组件来自 `features/`，令牌来自 `packages/design-tokens`），不掺推测。
> 用途：① UI v2 重设计的唯一结构依据；② 主题框架的三层契约（变量 / 区域 / 状态）在此定义。

---

## 0. 为什么先定骨架再谈主题

主题能改什么，取决于骨架暴露了什么。当前系统把样式直接写在组件上（5465 处 `gx-*` 类），
没有语义化的结构锚点，外部主题就只能改颜色值、无法改密度与层级。
所以：**骨架不只是设计依据，它就是主题框架的 API 表面。**

---

## 1. 骨架层级模型（唯一一套容器）

```
App
├── 主壳 Shell（在壳页 26/32）
│   ├── TopBar          56px   全局搜索 / 帮助 / 头像
│   ├── Body（横向三栏）
│   │   ├── L1 一级导航   224px（折叠 56px）  库列表 + 底部固定区 + 用户卡片
│   │   ├── L2 二级面板   240px（可缺省）     当前库的上下文列表
│   │   └── Content 内容区
│   │       ├── 视图标签条  44px（Tab 高 28）
│   │       ├── 主体
│   │       └── 状态条      28px
│   └── 浮层 Overlay（抽屉 / 弹窗 / 气泡 / Toast）
└── 独立页 Standalone（6/32，脱离主壳）
```

**层级上限三层**（L1 库 → L2 库内上下文 → 内容区），禁止 L3 侧边栏。

### 1.1 区域契约表（★ 主题框架的结构锚点）

`data-region` 是建议新增的结构锚点，供主题按区域覆写（当前代码尚未有，属框架补齐项）。

| 区域 | data-region | 尺寸 | 职责 | 可主题化 | 不可变约束 |
|---|---|---|---|---|---|
| 顶栏 | `topbar` | h 56 | 全局搜索 / 帮助 / 头像 | 底、边框、高度（有限） | 高度 56 恒定（桌面壳布局依赖） |
| L1 导航 | `l1` | w 224 / 折叠 56 | 库列表、底部固定区、用户卡片 | 底、项圆角、选中态 | 折叠态只留图标 + tooltip |
| L2 面板 | `l2` | w 240 | 当前库上下文（表列表 / 文档树 / 设置项） | 底、项高、选中态 | 不存在时内容区自动占满 |
| 内容区 | `content` | flex | 主体内容 | 底、内边距 | 最小可读宽度 |
| 视图条 | `viewtabs` | h 44（Tab 28） | 视图切换 | 底、Tab 圆角与选中 | Tab 高 28 恒定 |
| 主体 | `canvas-area` | flex | 表格 / 看板 / 文档 / 画布 | 底、栅格间距、密度 | 行高由视图类型决定 |
| 状态条 | `statusbar` | h 28 | 计数 / 同步态 / 只读标记 | 底、字号 | 高度 28 恒定 |
| 浮层 | `overlay` | — | 抽屉 / 弹窗 / 气泡 / Toast | 圆角、阴影、遮罩透明度 | z-index 分层不可改（见 layout.ts） |

### 1.2 交互状态锚点（主题必须覆盖的状态）

| 状态 | 语义名 | 现状 | 主题化要求 |
|---|---|---|---|
| 默认 | `rest` | Tailwind 静态类 | 必覆盖 |
| 悬停 | `hover` | `hover:` 变体 | 必覆盖 |
| 选中 | `selected` | `bg-gx-selected` / 白底 + 主色字 | 必覆盖 |
| 聚焦 | `focus` | 焦点环 | 必覆盖（可访问性硬要求） |
| 禁用 | `disabled` | opacity .5 | 必覆盖 |
| 只读 | `readonly` | 去边框去底色 | 必覆盖 |
| 拖拽中 | `dragging` | 表格 / 看板 / 树 | 建议覆盖 |

## 3. 五态契约（每个内容区都必须有）

| 态 | 呈现规则 | 反例 |
|---|---|---|
| ① 加载中 | 骨架屏，保持行高，禁止转圈导致跳动 | 用 spinner 占位，加载完高度跳变 |
| ② 空数据 | 说明 + 一个主行动；**区分「还没有」与「筛选后为空」** | 两种空态共用一句「暂无数据」 |
| ③ 出错 | 原因一行 + 重试；不吞错误码（可折叠展开详情） | 只写「出错了」 |
| ④ 无权限 | **就地渲染，不跳登录**；说清缺哪个权限、找谁要 | 重定向到登录页 |
| ⑤ 超长文本 | 标题 / 单元格 / 标签各自截断策略 + hover 全文 | 一刀切 `truncate` 导致信息不可读 |

## 4. 令牌契约（主题框架的变量层）

现状：`packages/design-tokens`（colors 106 行 / layout 90 行 / tailwind 143 行），
以 **TS 常量 → Tailwind 静态类** 的方式在构建期编译进 CSS。

### 4.1 令牌分组

| 组 | 数量级 | 说明 | 主题化优先级 |
|---|---|---|---|
| 表面 surface / bg / nav1 / nav2 / control / tableHeader | 8 | 层次底色 | P0 |
| 文字 textPrimary…textFaint | 5 | 五级文字层级 | P0 |
| 边框 hairline / border / borderStrong / dividerV | 4 | 分隔线 | P0 |
| 强调 accent / accentBg / accentHover / selected | 4 | 主色与选中 | P0 |
| 语义 success / warning / danger（+Bg） | 6 | 状态色 | P0 |
| 阴影 shadow sm/md/lg/xl | 4 | 当前为 rgba(0,0,0,x) 硬编码黑 | P1（暗色必须） |
| 圆角 radius 6 档 / 间距 spacing 10 档 | 16 | 密度 | P1 |
| 字号 fontSize 9 档 / 字重 4 档 | 13 | 排版 | P2 |
| z-index 分层 | 14 | 浮层层级 | ❌ 不可主题化 |

### 4.2 不属于主题的色彩（必须区分，否则主题会污染业务数据）

| 类别 | 位置 | 性质 |
|---|---|---|
| 用户可选内容色板 | `ColorPicker.tsx`（36 处）、`canvas-colors.ts`（28 处） | **业务数据**，用户自己选的颜色，主题不得改写 |
| 字段类型色 | `FIELD_TYPE_COLOR`（24 项） | 数据语义色，主题可微调但需保持可区分 |
| 头像取色板 | `AVATAR_PALETTE`（8 色） | 按昵称 hash 稳定取色，主题可替换但需保持色相分散 |

## 5. 骨架对主题框架的暴露面（结论前置）

| 层 | 契约 | 现状 | 主题化后 |
|---|---|---|---|
| 变量层 | CSS 变量集合 | ❌ 无（构建期常量） | ✅ 需改为运行时变量 |
| 区域层 | `data-region` 锚点 | ❌ 无 | ✅ 需补齐（让主题能按区域覆写） |
| 状态层 | 语义状态类 / `data-state` | 部分（hover/selected 有类） | ✅ 需补齐 rest/hover/selected/focus/disabled/readonly |
| 结构层 | 尺寸（56/224/240/44/28） | 硬编码在组件 | ⚠️ 建议变量化但需设上下限，避免主题把界面改坏 |

**一句话**：骨架已经够清晰、够收敛（零原生色类、零 dark 变体、单一容器模型），
缺的不是"重新设计"，而是**把结构锚点和变量层抽出来**——这正是主题框架要补的那层。
