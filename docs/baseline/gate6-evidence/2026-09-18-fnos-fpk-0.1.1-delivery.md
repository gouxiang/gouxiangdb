## 2. 主要变更点

### 2.1 【P0】修复：登录后主界面永久 loading（本次最关键的根因修复）

**根因**：飞牛第三方应用的 CGI 网关 `/usr/trim/bin/trim_http_cgi` 会把请求里的
`Authorization` 头当作**它自己的 fnOS 令牌**校验；我们的应用 JWT 不是合法 fnOS 令牌，
网关直接返回 `HTTP 200 + "invalid token"`（13 字节）并把请求**吞掉**，根本不转发给应用。

**证据**（同一浏览器、同一 token、同一 URL 的对照实验）：

| 请求头 | 响应 | 说明 |
| --- | --- | --- |
| `X-GX-Token: <jwt>` | `401 {"error":"Invalid token","code":"UNAUTHORIZED"}` | 到得了**我们自己的后端**（旧构建还不认这个头） |
| `Authorization: Bearer <jwt>` | `200 invalid token` | 被**飞牛网关**吞掉 |

nginx 访问日志旁证（`/usr/trim/nginx/logs/access.log`，响应体字节数即判据）：

```
15:24:29 POST /cgi/ThirdParty/gouxiangdb/index.cgi/api/auth/signup        200 355   ← 无令牌头，正常穿过
15:24:29 GET  /cgi/ThirdParty/gouxiangdb/index.cgi/api/v1/workspaces/...  200  13   ← "invalid token"，被吞
15:28:23 GET  /cgi/ThirdParty/gouxiangdb/index.cgi/api/auth/me            200  13   ← "invalid token"，被吞
```
（`invalid token` 恰为 13 字节；我们后端的 401 JSON 恰为 47 字节，可据此分辨响应来源。）

**修法**：应用 JWT 改用自定义头 `X-GX-Token` 携带，绕开网关校验。

- `apps/api/src/domain/org/authState.ts`：新增 `readBearerToken()`，
  `resolveActiveAuth` 先取 `Authorization: Bearer`，再回退 `X-GX-Token`（可带或不带 Bearer 前缀）。
  MCP / PAT 等外部客户端仍可用 `Authorization`，**向后兼容不变**。
- `apps/api/src/app.ts`：CORS `allowHeaders` 增 `X-GX-Token`。
- `apps/web/src/api/authHeader.ts`（新）：`authHeaders(token)` 单一出口，头部注释写清飞牛原因。
- 前端 8 处调用点全部改走 `authHeaders`：
  `api/client.ts`（4 处）、`features/settings/PersonalCenterDrawer.tsx`（XHR 上传头像）、
  `features/kb/useDocPersistence.ts`、`features/kb/WysiwygEditor.tsx`、
  `features/kb/hooks/useLinkResolve.ts`。
- `deploy/fnos/gouxiangdb/app/ui/index.cgi`：新增 `HTTP_X_GX_TOKEN → x-gx-token` 转发。

### 2.2 【P0】修复：点击应用后空白页（入口架构从"统一网关"改为"CGI 反代"）

**根因**：声明 `gatewayPrefix=/app/gouxiangdb` + `gatewaySocket=app.sock` 后，
`http://<nas>:5666/app/gouxiangdb/healthz` 返回 `200` 但 body 是**门户自己的 `invalid token`**——
请求根本没进应用，桌面点开即空白页。设备上唯一正常工作的三方应用 `com.fnos.dashboard`
走的正是 CGI 反代路线（其 changelog 亦写明"改用 fnOS 公开的 CGI 反代入口，
替代未对三方应用生效的网关注册"）。

**修法**：

- `deploy/fnos/gouxiangdb/app/ui/config`：`url` 改为 `/cgi/ThirdParty/gouxiangdb/index.cgi/`，删除 `gatewayPrefix` / `gatewaySocket`。
- 新增 `app/ui/index.cgi`（可执行 shell，参照设备上在跑的 `com.fnos.dashboard/ui/index.cgi`）：
  剥掉 `index.cgi` 前缀后用 `curl` 反代到 `127.0.0.1:${TRIM_SERVICE_PORT}`，
  处理无尾斜杠 302、`..` 越界 400、后端无响应 502、状态码/Content-Type 透传。
- `cmd/main`：后端改监听 **TCP 3001**（不再 unix socket），且**不再设 `GX_BASE_PATH`**
  （CGI 已剥前缀，再设会多期望一层前缀而 404）；stop 分支清残留 `app.sock`。
- `manifest`：新增 `service_port=3001` 与 `checkport=true`。
- `deploy/fnos/build-fpk.mjs`：新增**入口一致性自检（白屏闸门）**——
  `index.cgi` 存在且有 X 位、`app/ui/config` 为合法 JSON、入口禁带 `gatewayPrefix`/`gatewaySocket`、
  `url` 必须等于 CGI 前缀；web 构建 `VITE_BASE_PATH` 取同一 CGI 前缀。

### 2.3 【P1】修复：fpk 装不上（`code 10234 acl_get_file failed`）

**根因**：pnpm 默认布局的 `.pnpm` 深层目录 + 274 个符号链接，飞牛 ACL 设置失败。
**修法**：`--node-linker=hoisted` + `.bin` 实体化 + **node_modules 零符号链接硬闸门**
（此前 10 组对照实验定位，详见 `2026-09-18-lead-fnos-fpk-verify.md`）。
顺带修掉两处"假绿"：fnpack 校验失败仍 exit 0（改为以磁盘产物为准，且先清旧同名产物）、
better-sqlite3 只判 `build/Release` 空目录（改为必须真找到 `.node`）。

## 3. 安装方式

### 3.1 应用中心 UI 手动安装（推荐，最接近真实用户操作）

1. 登录飞牛 Web 管理端 `http://192.168.31.183:5666`。
2. 打开**应用中心** → 右上角「手动安装」（若未开启：SSH 后
   `sudo appcenter-cli manual-install enable`）。
3. 选择 `/vol1/1000/构想工作台-0.1.1.fpk`。
4. 依赖会自动带出 **Node.js v22**；安装参数留空（一次性 env 用 `gx.env` 仅 CLI 需要）。
5. 安装完成后点「打开」→ 应直接进入应用（无需再登录 NAS 之外的账号）。

> ⚠️ **若设备上已装 0.1.0**：实测 `appcenter-cli install-fpk` 对已安装应用只会打印
> `Application [gouxiangdb] is installed.` 并**跳过**（CLI 无 upgrade 子命令）。
> 因此命令行路径需先卸载再装（卸载**保留用户数据**，见 §4.3 实测）；
> UI 手动安装则可直接覆盖升级。

### 3.2 命令行安装（SSH，需 sudo）

```bash
# 1) 取包（已在设备上）
cp /vol1/1000/构想工作台-0.1.1.fpk /tmp/

# 2) 全新安装
sudo appcenter-cli install-fpk /tmp/构想工作台-0.1.1.fpk

# 2') 已装旧版：先卸载（保留数据）再装
sudo appcenter-cli uninstall gouxiangdb
sudo appcenter-cli install-fpk /tmp/构想工作台-0.1.1.fpk
sudo appcenter-cli start gouxiangdb

# 3) 校验
sudo appcenter-cli list                       # gouxiangdb | 构想工作台 | 0.1.1 | running
curl -s http://127.0.0.1:3001/healthz         # {"status":"ok",...,"version":"0.1.1"}
curl -s http://127.0.0.1:3001/readyz          # 五探针全 true
```

> 注：`appcenter-cli` **必须 sudo**，否则 `panic: ApplyPermission … rpcbroker: permission denied`。
> 中文用户名（如「戴静」）无法用 `ssh`/`scp`/`sshpass` 直接登录
> （`remote username contains invalid characters`），需改用 paramiko 或改用拉丁字母账号。
