## 3. AC-M2-1 对抗八条（S8 实测，`ac-m2-1.adversarial.test.ts` 等 50 例）

`src/routes/v1/org/__tests__/` 全目录本次实跑 **8 文件 50 例全绿**。八条对抗结论：

1. 真 API 逐级 POST 建 6 层部门链，物化 path 六段正确。
2. 用户经 `/members/:id/departments` 兼两个部门（主+兼），一人一主由部分唯一索引保证。
3. 自定义角色 R（manage_members）授 D2、Q 授第二兼岗部门、viewer 直授用户；
   `effective-roles` 并集含 R（经祖先链，来源标到授予部门 D2）/Q（部门）/viewer（user），三路径来源完整。
4. **调岗即时**：移出兼岗分支后下一次请求 R 消失、并列分支 Q 仍在；加回即恢复（无 sleep/缓存）。
5. owner 停用 U：旧 tv token 对 `/api/auth/me` 与 `/api/v1/org/members` 的下一次请求均 401；
   两面响应体均带 `code:"UNAUTHORIZED"`；停用后登录 401 同码。
6. 同一旧 token 第二次请求（模拟 iframe 刷新）仍 401。
7. owner 自停用 400；唯一在岗 owner（含经部门授予子树展开者）停用 409 CONFLICT；
   存在第二在岗 owner 时可停用其一（200，不过度拦截）。
8. 匿名 `/api/public/s/:token` 在停用无关成员后仍 200（公开通道零次查 users 表，另有特征测试锁定）。

几何注记：计划文字「单链上兼 D3 与 D6、移 D3 后 R 消失 Q 仍在」在纯单链上不成立——D6 的祖先
闭包天然含 D2，故第二兼岗点放在 A1 下的**并列分支 B1**（path `/{A1}/{B1}/`，祖先不含 A2），
6 层深度与双兼岗对抗强度不变；已在用例注释写明，防后人误读为实现错误（team-lead 已认可）。

### 3.1 S8 对抗抓出并修复的真缺陷（commit `c2b2e9b`）

`/api/auth/me` 等鉴权拦截是 `auth.ts` 手工 `c.json`，未走统一 `errorResponse`，401 响应体只有
`{error}`、缺机器码 `code`，不满足 AC 的「响应体 code=UNAUTHORIZED」。修复（纯增补，成功响应与
HTTP 状态码零变化）：auth.ts 内 **10 处鉴权 401 补 `code:"UNAUTHORIZED"`**（login 未知邮箱/坏口令/
停用、GET /me 两处、PATCH /me、改密两处、注销两处），INVITED 登录 **403 补 `code:"FORBIDDEN"`**。
业务校验 400/404/409 本轮一律未动。零破坏依据：web client 只按 401 状态码处理不读 error.code，
S0 auth-current 只断言状态码。`meAvatar.ts` 另有两处同类裸 401 不在 AC 范围，列遗留（§7）。

## 4. 查询计数与 500 人性能（本次实跑，未照抄）

口径：SQLite connector 不支持 Prisma query 日志事件，沿用 M1/S9 既定「Prisma 模型委托往返」
客观计数（同 `db.ts instrumentPrisma` 与 roles-eval 测试），非物理 SQL 条数。

- `effectiveRoleRows(userId)`：常量 **3 次**往返（deptMember 归属 -> department 祖先名 ->
  roleAssignment 一条 OR 取直授+祖先 dept 授，include role）；叠加到 12 层、更多兼岗后仍为 3，
  与部门层数/兼岗数无关（`s8-query-count.test.ts` 断言 <=3 且夹具加倍后计数不变）。
- `listMembers`（无 deptId 主列表）：恒定 **4 次**（user.count + user.findMany +
  deptMember IN + roleAssignment IN），10 人与补到 500 人实测同为 4，无 N+1；带 deptId 另加
  2 次子树解析（findFirst+findMany）。
- 500 ACTIVE 用户 + 6 层部门 + 确定性随机 1~3 兼岗（种子 20260915，可复现），真 HTTP
  （`s8-members-perf.test.ts`）。S9 收口共实跑三轮，数字随机器负载抖动，全部远优于目标：

  | 轮次 | 5 页 median | 5 页 p95 | 首页 warmP95 | 首屏三接口并行 |
  |---|---|---|---|---|
  | **提交前最后复核（17:20）** | **2.66 ms** | **7.21 ms** | **2.42 ms**（cold 1.80 / warmMedian 1.86 / max 2.60） | **2.09 ms** |
  | S9 首轮（17:05） | 4.60 ms | 11.51 ms | 6.45 ms（cold 2.54 / warmMedian 4.21 / max 6.70） | 3.63 ms |
  | S8 提交当次 | 3.27 ms | 8.82 ms | 7.94 ms | 6.43 ms |

  - 管理面目标 P95<150 ms，三轮最差 p95 11.51 ms，余量 >13 倍；并行首屏为 M3 导航 <1s
    硬指标的 M2 基线。
  - P95 仅打印留证、不据此 fail；另设 median<150 / max<1000 宽松防回归上界，三轮均通过。

## 7. 组织审计事件名表（S6 新增，JSONL，写前脱敏）

审计仍为零依赖 JSONL：每行一条，append 到 `$GX_AUDIT_DIR/audit.logl`
（生产 `/var/log/gouxiangdb/audit.logl`，logrotate copytruncate）。脱敏：键名小写含
`password/passwd/token/secret/authorization/bearer/jwt/cookie` 子串即递归替换为 `[REDACTED]`
（`audit.ts redactSecrets`，深度>4 标 `[DEPTH]`）；写失败只告警不阻断业务。

| event | 触发端点 | HTTP status | detail（示例，均无敏感值） |
|---|---|---|---|
| `signup`（既有） | POST /api/auth/signup | 200 | actorId |
| `login_success` / `login_failure`（既有） | POST /api/auth/login | 200 / 401/403 | failure 带 reason（unknown_email/disabled/bad_password/invited） |
| `change_password`/`account_delete`/`avatar_delete`（既有） | 对应 /api/auth/me* | 200 | actorId |
