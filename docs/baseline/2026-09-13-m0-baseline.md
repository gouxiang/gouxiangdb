## 4. 结构性事实（M0 "不破坏基线"的依据）

- 8 个 api 测试文件全部直接 import 路由模块/域函数（fake prisma），**无任何测试 import `src/index.ts`**。
  因此 S2/S3/S4 对入口 `index.ts`、构建链路、配置闸门的改动不在测试求值路径上。
- vitest 下 `NODE_ENV=test`，S3 配置闸门对 test/development 放行，仅 production fail-closed。
- `@gx/shared-types` 无 build 脚本、发布裸 TS（exports 指向 `./src/index.ts`），
  开发态靠 tsconfig paths / vite alias 消费；生产可运行性由 S2 esbuild 内化打包解决。
- Prisma 迁移目录 11 个（含 `20260911233000_kbdoc_content_version`），S4 readyz 迁移对账基线 = 11。
