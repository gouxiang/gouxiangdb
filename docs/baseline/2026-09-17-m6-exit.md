## 3. 旧路由"字节零 diff"的准确口径（对 DoD 措辞的修正登记）

DoD §12-7 原文写「旧路由**字节**零 diff」。**M6 实施期实际并非字节零 diff**，必须如实写清：

| 文件 | 净增删（`git diff --numstat d7ff0ac..HEAD`） | 性质 |
|---|---|---|
| `apps/api/src/routes/records.ts` | +14 / −324 | **纯移动**：事务体搬入 `domain/recordWrite.ts`（+386），原文件 re-export 保持既有导入点不变 |
| `apps/api/src/routes/kb/docs.ts` | +7 / −38 | **纯移动**：编排搬入 `domain/kbDocWrite.ts`（+77） |
| `apps/api/src/routes/kb/shared.ts` | +0 / −6 | 同上（协助函数搬出） |
| `apps/api/src/routes/v1/index.ts` | +4 / −0 | 只增：挂 `/pats` 子面 |
| `apps/api/src/routes/v1/pats.ts` | +103 / −0 | 新增文件（M6 自有面） |

即：**新增行全部落在新文件/新面，旧文件减少的行是"搬到 domain 后删除本地副本"**。因此准确口径是
**旧路由"对外行为零 diff"**，由三方证据支撑：

1. **S0 characterization golden**：`src/__tests__/m6-s0-characterization.test.ts` **8 例全绿**（本轮实测 5384ms），
   锁住旧行为四组：kb PUT content 409 `VERSION_CONFLICT`+`currentVersion`、旧记录列表 200 形状、
   `/api/v1/meta` 200 形状、**全局 1MB body 对 `/api` 仍 413 `PAYLOAD_TOO_LARGE`**（M6 未放宽 `/api`）。
2. **旧用例零改写**：常规门收集总数恒 2089（§1.1）——旧用例既没被删改，也没有被新增覆盖掉。
3. **纯移动特征**：删除行数与 `domain/` 新文件新增行数成对（−324 / +386 等），且原文件保留 re-export
   以维持既有 `import` 路径。

> 建议：后续里程碑不要把"字节零 diff"写成对**纯移动重构**的硬门；应写成"对外行为零 diff + 我方路由文件 diff 仅限纯移动"。

## 5. fpk / Docker 产物核查（S9 明细点名三项）

| 核查项 | 结论 | 证据 |
|---|---|---|
| **SDK 在生产依赖** | 通过 | `apps/api/package.json` 的 `@modelcontextprotocol/sdk` 在 **`dependencies`**（`1.30.0`，非 devDeps）；`pnpm-lock.yaml` 精确 pin `@modelcontextprotocol/sdk@1.30.0`。Docker 与 fpk 的运行时 `package.json` 都**从 `apiPkg.dependencies` 生成**（只剔 `@gx/*`），故 SDK 会被装进镜像/包 |
| **stdio bin 产物** | 通过（含一条 advisory） | `scripts/build.mjs` 双入口产出 `dist/index.js` + `dist/mcp-stdio.js`；Dockerfile `COPY --from=builder /app/apps/api/dist ./dist` **整目录拷贝**（`deploy/docker/Dockerfile:91`）；fpk `copyDir(distSrc, server/dist)`（`deploy/fnos/build-fpk.mjs:104`）同样整目录，且 `build.mjs` 在产物缺失时**直接报错退出**（不会静默漏包） |
| **反代 11m** | 通过（口径一致） | `deploy/caddy/Caddyfile` 的 `request_body { max_size 12MB }`；应用侧 `/mcp` 档 11MB（`GX_MCP_BODY_LIMIT`）→ **1MB 余量**，runbook §4.2 已写"改大必须同步改反代" |

**advisory（不阻塞，登记备查）**：

1. `deploy/fnos/build-fpk.mjs:103` 只**显式断言** `dist/index.js` 存在，未断言 `dist/mcp-stdio.js`。
   由于 `dist` 是整目录拷贝且 `build.mjs` 已双入口自检，实际漏包风险低；若要把 stdio 出口做成硬门，
   可在该脚本补一行 `existsSync(dist/mcp-stdio.js)` 断言（**属部署物改动，本片不动**）。
2. Docker/fpk 生成的运行时 `package.json` **不带 `bin` 字段**（只带 `dependencies`），因此容器/包内**没有**
   `gx-mcp-stdio` 这个命令名，必须以 `node dist/mcp-stdio.js` 路径形式调用。runbook §3.2 与接入说明 §5
   已统一用路径形式书写，与产物实态一致。

## 6. 出口姿态（硬事实）

| 项 | 出口值 | 锚点 |
|---|---|---|
| MCP 面门控 | `GX_ENTERPRISE_ORG` 控制 `/mcp` **与** `/api/v1/pats`（同门控，C-5）；off 时两者均 404 | `src/app.ts:147-156` |
| **默认挂载姿态** | `GX_ENTERPRISE_ORG` **出厂默认 on**（`!== "off"`，M2 既有设计）→ `/mcp` 与 `/api/v1/pats` 在**所有部署上默认挂载**；设 `=off` 时二者**顶层 404**，AI 接入面整体摘除、与未升级不可区分。**风险提示**：默认挂载意味着一个「需 PAT 凭据、但 body 上限放宽到 11MB」的入口默认存在——访问控制靠 **PAT 认证 + M4 可见集闸门**两层；如需最小暴露姿态，运维侧显式设 `GX_ENTERPRISE_ORG=off`（runbook §1.1 紧急收回） | `src/config.ts:315`（`:225`/`:314` 注释）；出厂模板均不设该变量（`deploy/env.conf.example`、`deploy/docker/gouxiangdb.env.example`、`apps/api/.env.example`、`deploy/fnos/**`） |
