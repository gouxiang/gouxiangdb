## 4. 被锁的现状契约（S0 三组特征测试，只增测试不改行为）

新增目录 `apps/api/src/domain/org/__tests__/characterization/`，3 文件 34 用例：

### 4.1 `auth-current.test.ts`（10 用例）— 鉴权现状
- `getUserId`：无 Authorization / 非 Bearer / 坏签名 -> `null`（不抛错）；签名形态 `(c) => Promise<string|null>`。
- 真 signup/login 得到的 token：HS256、payload 含 `userId`、`exp-iat = 7*24*3600`（7 天）。
- signup/login 成功体为 `{ token, user }`；`publicUser` 键集合锁定为
  `id/email/displayName/username/phone/avatarUrl/bio/createdAt/updatedAt` 九键、不含 `passwordHash`（M2 只许加不许减）。
- login：错误口令/未知邮箱 -> 401；signup 非法输入 -> 400、重复邮箱 -> 409。
- `GET /auth/me`：无 token/坏 token -> 401；合法 token 且用户存在 -> 200。
- 这些是对 ACTIVE 用户 M2 前后都成立的不变量（S2 加查库后必须逐值等价）。

### 4.2 `resource-rbac-current.test.ts`（19 用例）— 资源 RBAC 五角色矩阵（M2 最高红线）
- `permissionsForRole` 五角色布尔矩阵逐值锁定：
  - owner `[MB,MS,ED,C,V]=[T,T,T,T,T]`；creator `[F,T,T,T,T]`；editor `[F,F,T,T,T]`；
    commenter `[F,F,F,T,T]`；viewer `[F,F,F,F,T]`；并锁「返回副本不污染真源」。
- 真库 `roleOf/permissionsOf`：五成员各取其角色；非成员 undefined + 权限全 false。
- 真 Hono + 真 JWT（用同一 HS256 密钥直接签 `{userId}`）打通
  getUserId 验签 -> 真库取 role -> requireCan* 整条链：
  - view 五角色全 200；editData 仅 owner/creator/editor；manageSchema 仅 owner/creator；
    manageBase 仅 owner；comment 除 viewer 外四角色；其余 403。
  - 已登录非成员对五类动作全 403；无 token -> 401。
- M2 组织角色（roles/role_assignments）不接入这些判定，S9 复跑本文件必须逐值绿。

### 4.3 `public-share-current.test.ts`（5 用例）— 匿名公开外链与用户解耦（总监裁决 1）
- 不带 Authorization -> 200；带某登录用户合法 Bearer -> 仍 200（授权头被忽略）。
- 在底层 `prisma.user` 读委托上装探针：一次 `GET /s/:token` 期间对 **users 表零次查询**。
- **物理删除分享创建者用户后外链仍 200**（kb_docs.createdBy 仅字符串、无 FK，匿名通道不 join users）；
  这比「停用」更强且 M2 前后都成立——DISABLED 只是 users 行内状态，更不可能影响匿名链接。
- 失效 token -> 404。将计划 §5-D.5「停用不联动吊销匿名外链」钉成可执行断言。
